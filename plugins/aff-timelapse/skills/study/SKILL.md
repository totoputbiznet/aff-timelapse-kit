## จังหวะการทำงาน — รายงานแล้วไปต่อเอง

จบขั้นไหน **รายงานผลสั้นๆ 1-3 บรรทัดแล้วทำขั้นถัดไปต่อทันที** ไม่ต้องขออนุญาต
รายงานให้บอก**ผลที่วัดได้** (กี่ช็อต ช็อตละกี่วิ มีเสียงไหม) ไม่ใช่บอกว่ากำลังจะทำอะไร

**หยุดรอผู้ใช้เฉพาะ 3 กรณีนี้เท่านั้น:**

| หยุดเมื่อ | ตัวอย่าง |
|---|---|
| ต้องให้ผู้ใช้**ไปทำเองบนเว็บ** | โหลดไฟล์คลิปมาวางใน `research/clips/` |
| ต้องให้ผู้ใช้**ตัดสินใจ** | ข้อค้นพบขัดกับกฎที่ตัดสินไปแล้ว จะเอายังไงต่อ |
| **ติดปัญหาที่แก้เองไม่ได้** | ไม่มี `ffmpeg` · ไฟล์เสีย · ไม่มี `tools/study-clip.mjs` |

## ⛔ กติกาที่ต้องอ่านก่อนเริ่ม

**นี่คือการศึกษารูปแบบ ไม่ใช่การลอกฟุตเทจ** ห้ามเสนอให้ทำคลิปซ้ำคลิปต้นฉบับ
ข้อเสนอไหนเข้าใกล้การทำซ้ำ ให้รันสกิล `facebook-original-content-check` กับข้อนั้นก่อนเขียนลงเอกสาร

**ห้ามแก้ `CLAUDE.md` · `Timelapse_Blueprint_V1.md` · `scenes/*/storyboard.md` เอง**
เอกสารพวกนั้นเป็นกฎที่ตัดสินไปแล้ว สกิลนี้เขียนได้แค่ว่า "ข้อค้นพบนี้ขัดกับกฎข้อไหน" แล้วให้ผู้ใช้ตัดสิน

**ห้ามเดาตัวเลขที่อ่านไม่ได้** อ่านไม่ได้ให้เขียนว่าอ่านไม่ได้ · ยอดวิวที่ Facebook ปัดมาแล้วให้จดตามที่เห็นพร้อมวันที่

## ขั้นที่ 1 — เอาไฟล์คลิปมาก่อน

**ต้องมี `.mp4` จริง สตรีมจากหน้าเว็บวัดไม่ได้** วัดมาแล้วสองรอบ:

| ลองแล้ว | ผลที่ได้ |
|---|---|
| อ่าน `video.duration` ในแท็บที่ควบคุม | บางครั้ง `readyState 0` ค้าง ไม่มี request วิดีโอออกไปเลย |
| `video.currentSrc` เพื่อดึง URL ไฟล์ | ว่างเปล่า — Facebook เล่นผ่าน MSE (blob) ไม่มี URL ให้ดึง |
| วาดเฟรมลง canvas แล้ววัดในหน้าเว็บ | seek บนวิดีโอ MSE ค้าง ไม่ยิง event `seeked` |
| กวาดแท็บ Reels หาลิงก์ | โหลดค้างที่ 10 คลิป ไม่โหลดต่อ |

→ **บอกผู้ใช้ให้กดปุ่ม Download บนหน้ารีล แล้ววางไฟล์ที่ `research/clips/`**
ตั้งชื่อไฟล์ตามยอดวิว เช่น `29m.mp4` จะได้ไม่ต้องเดาทีหลัง แล้วรอ

ได้ไฟล์แล้วเช็คว่ามาถึงจริง: `ls research/clips/`

## ขั้นที่ 2 — วัดด้วยคำสั่ง ไม่ใช่ด้วยตา

```bash
node tools/study-clip.mjs research/clips/<ไฟล์>.mp4
```

ได้มา 4 อย่าง: **ตารางช็อต** (กี่ช็อต ช็อตละกี่วิ คะแนนรอยคัต ความหนาแน่นลายเส้น) ·
**การเคลื่อนกล้องในช็อต** · **เสียง** (มีสตรีมไหม ดังกี่ dB) · **แถบภาพตัวแทนช็อต** `<ชื่อ>-shots.png`

ช็อตน้อยผิดปกติให้ลดเกณฑ์แล้ววัดซ้ำ: `--thresh 0.12`
คัตจากภาพกว้างไปโคลสอัพ**ในฉากเดียวกัน** สี แสง พื้นหลังยังเหมือนเดิม คะแนนจึงต่ำกว่าคัตข้ามฉาก

### ⛔ สองอย่างนี้คนละเรื่องกัน — เคยอ่านผิดมาแล้ว

| | คืออะไร | เห็นที่ไหน | แก้ที่ไหนของเรา |
|---|---|---|---|
| **คัตไปโคลสอัพ** | เปลี่ยนช็อตทันทีข้ามเฟรมเดียว แล้วมักคัตกลับมุมหลัก | ตารางช็อต | **บล็อก `Camera:`** — สั่งให้โมเดลทำคัตในคลิปเดียว |
| **ซูม / ดอลลี่** | เคลื่อนกล้อง ภาพค่อยๆ ใหญ่ขึ้นหลายเฟรม | หัวข้อ "กล้องขยับในช็อต" | **บล็อก `Camera:`** เหมือนกัน แต่คนละคำสั่ง |

**⭐ คัตในคลิปเป็นสิ่งที่โมเดลวิดีโอทำเองได้ ไม่ต้องรอไปตัดต่อ** — และเมื่อทำในคลิปเดียว
มัน**ไม่ชนกับ frame-to-frame** เพราะคลิปยังเริ่มและจบที่ภาพนิ่งเดิม คัตเกิดตรงกลาง
`check-scene.mjs` เทียบแค่เฟรมแรกกับเฟรมสุดท้าย จึงยังผ่านตามเดิม

⚠️ **จากไฟล์อย่างเดียวบอกไม่ได้ว่าคัตนั้นมาจากโมเดลหรือมาจากการตัดต่อ** — วัดได้แค่ว่า
คัตอยู่ตรงไหนและช็อตขนาดไหน ห้ามเขียนในรายงานว่า "เขาให้โมเดลทำ" หรือ "เขาตัดต่อเอา"
ราวกับรู้ **เขียนว่าเห็นคัตที่วินาทีไหน แล้วแยกข้อสันนิษฐานออกมาเป็นอีกบรรทัด**

ทางที่ควรลองก่อนเสมอคือ**สั่งในพรอมต์วิดีโอ** เพราะถูกกว่าและไม่ต้องแตะโครง 3 คลิป
ถ้าโมเดลทำไม่ได้จริงค่อยถอยไปทำที่ชั้น `assemble`

## ขั้นที่ 3 — เปิดแถบภาพ แล้วจัดประเภทช็อต

`<ชื่อ>-shots.png` คือเฟรมกลางของทุกช็อตต่อกัน **ต้องเปิดดูจริง** ตัวเลขลายเส้นเป็นแค่ตัวชี้
สนามหญ้าโล่งกว้างก็ลายเส้นห่างได้เหมือนโคลสอัพ

จัดทุกช็อตเป็น **กว้าง / กลาง / โคลสอัพ** แล้วนับว่าสลับกันเป็นลายอะไร
(เช่น กว้าง→ใกล้→กว้าง→ใกล้ หรือ กว้างยาวๆ แล้วค่อยมีใกล้ตอนท้าย)

จากแถบภาพให้อ่านต่ออีก 3 ข้อ — ตัวเลขตอบให้ไม่ได้:

| อ่านอะไร | ทำไมสำคัญ |
|---|---|
| ในช็อตนั้น **เดิน** หรือ **ลงมือทำ** | โครงเราใช้วงจร `walk in … walk out` ซึ่งกินวินาทีไปกับการเดิน |
| คนอยู่ในเฟรม **เต็มตัว** หรือเห็นแค่ **มือ/ท่อนแขน** | โคลสอัพที่เห็นแค่มือทำให้กฎ FULL BODY ของเราใช้ไม่ได้ในช็อตนั้น |
| ช็อตสุดท้าย **มีคนอยู่ไหม** | เฟรมจบของเราต้องไม่มีคน เพราะต้องตรงกับ `phase3.png` |

## ขั้นที่ 4 — เขียน `research/reels/<ยอดวิว>-<reel-id>.md` ทันที

## โครงการตัด

## ขั้นที่ 5 — สะสมลง `timelapse_master_prompt.md`

**ต่อท้าย ไม่ใช่เขียนทับ** ไฟล์นี้โตขึ้นทุกครั้งที่ศึกษาคลิปใหม่

- ข้อค้นพบใหม่ลงหัวข้อ **"เจอบางคลิป"** ก่อนเสมอ พร้อมวงเล็บว่าเจอกี่คลิปจากกี่คลิป
- ข้อที่ขยับถึง **≥ 4 ใน 5 คลิป** ให้เลื่อนขึ้นหัวข้อหลัก
- ทุกข้อต้องอ้าง **คลิปไหน วินาทีไหน** — ข้อที่อ้างหลักฐานไม่ได้ให้ตัดทิ้ง
- ทุกข้อเสนอต้องระบุ**ปลายทาง**ว่าลงช่องไหน: บล็อก `Camera:`/`Action:`/`Overall:`/`Sound Effects:`
  ของพรอมต์วิดีโอ · คีย์ `scene`/`camera`/`style` ของ JSON ภาพ · CAMERA LOCK CARD ·
  ขั้นตอน `assemble` · หรือหัวข้อใน Blueprint
- ข้อที่ขัดกับกฎที่ตัดสินไปแล้ว ให้เขียนไว้ในหัวข้อ **"ข้อที่ขัดกับกฎ"** พร้อมอ้างว่าขัดกับบรรทัดไหน
  **แล้วหยุดถามผู้ใช้** อย่าตัดสินใจแทน

**ไฟล์นี้เป็นรายงานวิเคราะห์ ไม่ใช่ที่เก็บเทมเพลตพรอมต์** ห้ามใส่พรอมต์พร้อมก๊อปลงไป

## ขั้นสุดท้าย — ส่งมอบ

1. บอก path ของไฟล์บันทึกและหัวข้อที่เพิ่มเข้า `timelapse_master_prompt.md`
2. สรุป **3 ข้อที่ต่างจากงานเรามากที่สุด** พร้อมบอกว่าแต่ละข้อแก้ที่ชั้นไหน
3. ถ้ามีข้อที่ขัดกับกฎ **ยกให้ผู้ใช้ตัดสินเป็นคำถามชัดๆ** ไม่ใช่เขียนแล้วปล่อยผ่าน
