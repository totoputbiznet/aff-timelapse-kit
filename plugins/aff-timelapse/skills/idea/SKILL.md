## จังหวะการทำงาน — รายงานแล้วไปต่อเอง

จบขั้นไหน **รายงานผลสั้นๆ 1-3 บรรทัดแล้วทำขั้นถัดไปต่อทันที** ไม่ต้องขออนุญาต
รายงานให้บอก**ผลที่วัดได้** (ได้ไฟล์อะไร กี่รูป ผ่านหรือไม่ผ่าน) ไม่ใช่บอกว่ากำลังจะทำอะไร

**หยุดรอผู้ใช้เฉพาะ 3 กรณีนี้เท่านั้น:**

| หยุดเมื่อ | ตัวอย่าง |
|---|---|
| ต้องให้ผู้ใช้**ตัดสินใจ** | เลือกไอเดีย · รับหรือไม่รับภาพ · จะเขียนทับของเดิมไหม |
| ต้องให้ผู้ใช้**ไปทำเองบนเว็บ** | ยิงภาพหรือวิดีโอที่ Higgsfield |
| **ติดปัญหาที่แก้เองไม่ได้** | Chrome ไม่เชื่อมต่อ · ไม่มีไฟล์ที่ต้องใช้ · คำสั่งที่ต้องใช้ไม่มีในเครื่อง |

นอกจากสามข้อนี้ **ห้ามถามว่า "จะให้ทำต่อไหม"** — ทำต่อได้เลย
ขั้นที่พังไม่ได้แปลว่าต้องหยุดทั้งงาน **ทำขั้นที่เหลือให้จบแล้วค่อยบอกว่าขั้นไหนไม่สำเร็จเพราะอะไร**

## ขั้นที่ 1 — เสนอไอเดีย 4 แบบ ให้ผู้ใช้กดเลือก

คิดไอเดีย 4 แบบตามกติกาข้างล่าง แล้ว**ถามด้วยเครื่องมือ `AskUserQuestion`** ไม่ใช่พิมพ์ตารางให้ตอบเป็นเลข
เรียกครั้งเดียว คำถามเดียว 4 ตัวเลือก — ระบบเติมช่อง **Other** ให้เองเสมอ

| ช่อง | ใส่อะไร |
|---|---|
| `header` | `ไอเดีย` (จำกัด 12 ตัวอักษร ห้ามยาวกว่านี้) |
| `question` | `จะทำไอเดียไหนดี` |
| `label` | ชื่อไอเดียสั้นๆ 1–5 คำ เช่น `ระเบียงคอนโดนั่งเล่น` |
| `description` | 1 ประโยค — พื้นที่ + ปัญหาที่แก้ |
| `preview` | **รายละเอียดเต็มของไอเดียนั้น** ดูหัวข้อข้างล่าง |

**`preview` ต้องมี 3 บรรทัดนี้ครบทุกตัวเลือก** — มันแทนคอลัมน์ของตารางเดิม
ผู้ใช้เลื่อนดูทีละอันแล้วเห็นครบพอที่จะตัดสินใจได้ ไม่ต้องถามซ้ำ:

```
พื้นที่:        <ชนิดพื้นที่ + สภาพก่อนทำ>
สินค้าอยู่ตรงไหน: <มุมไหนของเฟรม เด่นยังไง>
ทำไมจะจี๊ด:      <before/after ต่างกันตรงไหนจนคนหยุดดู>
```

**⛔ ห้ามพิมพ์ตารางไอเดียซ้ำนอกกล่องเลือก** ข้อมูลเดียวกันสองที่ทำให้ผู้ใช้อ่านสองรอบ
กล่องเลือกคือที่เดียวที่ไอเดียอยู่

**กติกาการคิดไอเดีย:**

- **พื้นที่ต้องเป็นบ้านไทยจริง** — ระเบียงคอนโดแคบๆ · หน้าบ้านทาวน์เฮาส์ · ห้องนั่งเล่นทาวน์โฮม ·
  ข้างบ้านที่เป็นพื้นปูน · ดาดฟ้า · มุมครัวหลังบ้าน **ไม่ใช่บ้านฝรั่งในนิตยสาร**
- **ไอเดียต้องต่างกันจริงทั้ง 4 ข้อ** ไม่ใช่ห้องเดิมเปลี่ยนสี — ต่างที่พื้นที่ ต่างที่ปัญหาที่แก้
  มีแค่ 4 ช่อง **ข้อที่ไม่คุ้มจะอยู่ในรายการให้ตัดทิ้ง อย่าเติมให้ครบจำนวน**
- **ต้องมีพื้นที่ที่ "ก่อน" ดูแย่จริง** — รกจริง โล่งจริง เก่าจริง ไม่ใช่ห้องสวยอยู่แล้วแค่เติมของ
  ยิ่ง Phase 1 ดูไม่น่าอยู่เท่าไหร่ ตอน Phase 4 ยิ่งจี๊ด
- **สินค้าต้องเป็นพระเอกของ Phase 4** ไม่ใช่ของประดับที่มองข้ามได้
  ถามตัวเองว่า "ถ้าเอาสินค้านี้ออก ภาพ Phase 4 จะต่างจากเดิมไหม" ถ้าไม่ต่าง = ไอเดียตก
- **อย่างน้อย 1 ข้อต้องเป็นงานที่ดู "มีอะไรให้ทำ"** (ต้องเจาะ ต้องประกอบ ต้องทาสี)
  เพราะ Phase 2 กับเสียง ASMR จะสนุกกว่างานที่แค่ยกของมาวาง
- ⭐ **ให้น้ำหนักกับไอเดียที่สินค้าเองมีจังหวะ "กางออก / คลี่ออก / ยกขึ้น / พับลง"**
  ถอดจากรีลจริง: คลิป 50 กับ 25 ล้านวิว ใช้ **4 วินาทีเต็มกับร่มคันเดียว**
  (พับอยู่ → เอียงขึ้น → เริ่มกาง → กางเต็ม) เป็นเหตุการณ์ที่ยาวที่สุดของคลิปและเป็น payoff
  ของชิ้นเดียวที่กางออกได้ **กินเวลาได้หลายวินาทีโดยที่ภาพยังเปลี่ยนตลอด**
  ซึ่งแก้ปัญหา "seg3 มีแค่ 8 วิ แต่ต้องจัดของเยอะ" ได้ตรงจุด
  สินค้าที่เข้าข่าย: ศาลา ร่ม กันสาด ฉากกั้นพับได้ ชิงช้า ราวตากผ้าพับได้

**ผู้ใช้กด Other แล้วพิมพ์โจทย์ของตัวเองมา** = เขาอยากได้อย่างอื่น
คิดใหม่ตามที่เขาบอกแล้วเปิดกล่องเลือกใหม่อีกรอบ **ห้ามเลือกเอง ห้ามเดาว่าเขาหมายถึงข้อไหน**

### เทมเพลต CAMERA LOCK CARD

```
=== CAMERA LOCK ===
SCENE ID:        <scene-slug>
พื้นที่:          <ชนิดพื้นที่ + ขนาดโดยประมาณ + ทิศ>
จุดยืนกล้อง:      <ยืนตรงไหน มองไปทางไหน ผ่านอะไร>
ความสูงเลนส์:     <เมตร จากพื้น>
ระยะถึงฉากหลัง:   <เมตร>
เลนส์:            <mm> full-frame · กล้องขนานพื้น ไม่ก้มไม่เงย ไม่มี tilt
สัดส่วน:          9:16 แนวตั้ง
แสง:              <ทิศแสง + ช่วงเวลา + เงาทอดไปทางไหน>

หมุดอ้างอิง — ต้องอยู่ตำแหน่งเดิมเป๊ะทั้ง 4 เฟส:
  1. <ของใกล้ — ขอบวงกบ ขอบเสา ขอบผนัง> อยู่ <ตำแหน่งในเฟรม>
  2. <ของระยะกลาง — ราวกันตก ขอบเคาน์เตอร์ ขอบรั้ว> อยู่ที่ <%> ความสูงเฟรม
  3. <ของไกล — แนวตึก เส้นขอบฟ้า แนวต้นไม้> อยู่ที่ <%> ความสูงเฟรม
  4. <เส้นบนพื้น — รอยต่อกระเบื้อง แนวอิฐ> วิ่งไปทาง <ทิศ>

โซนวางสินค้า:     <มุมไหนของเฟรม> — ต้องโล่งสนิทใน Phase 1
```

> ⭐ **ตัวเลข % ในใบนี้ตอนแรกเป็นแค่เป้า** โมเดลจะไม่ทำตามเป๊ะและไม่เป็นไร
> **พอรับภาพ Phase 4 แล้ว ต้องกลับมาวัดตำแหน่งจริงในภาพ แล้วเขียนทับตัวเลขในใบนี้**
> เพราะ Phase 1 กับ 2 อ้างอิงจากใบนี้ ไม่ได้อ้างจากพรอมต์ Phase 4
> ใบที่ตัวเลขไม่ตรงกับภาพจริง = พรอมต์แก้ภาพจะสั่งให้โมเดล "รักษา" เส้นที่ไม่มีอยู่จริง
> ซึ่งแย่กว่าไม่สั่งอะไรเลย

**หมุดอ้างอิงคือสิ่งที่ตัดสินว่างานจะสำเร็จหรือไม่** เลือกให้ถูก:

- ต้องเป็น **เส้นตรงยาว** ไม่ใช่จุดเล็กๆ (ขอบผนังดี · กระถางไม่ดี)
- ต้องอยู่ **คนละระยะกัน** ใกล้-กลาง-ไกล ถ้าเลือกของที่อยู่ระยะเดียวกันหมด กล้องเลื่อนหน้า-หลังแล้วจับไม่ได้
  ถ้าฉากมีทั้งพื้นและเพดานในเฟรม ให้เก็บเส้นจากทั้งสองอย่าง จะได้ 5 เส้นครอบทุกทิศ
- ต้อง **ไม่ถูกเอาออกใน Phase 1** อย่าเลือกของที่ตัวเองจะสั่งลบทิ้ง
- ⚠️ **ต้องไม่ใช่พื้นผิวที่สินค้าไปติดทับ หรือรอยต่อที่ติดกับพื้นผิวนั้น**
  สินค้าที่ติดทับผนัง (แผ่นระแนง · วอลเปเปอร์ · กระเบื้องแปะ · แผ่นกันความร้อน) มีความหนา
  มันจะดันแนวรอยต่อผนัง-พื้นและผนัง-เพดานออกมาไม่กี่เซนติเมตรใน Phase 4
  ตัวเองไม่รู้ตัวแล้วจะไปตัดสินว่า "มุมกล้องเลื่อน" ทั้งที่กล้องไม่ได้ขยับ
  → เลือกของที่ **ลอยพ้นผนัง** แทน เช่น วงกบประตู ราวกันตก เส้นขอบฟ้า รอยต่อกระเบื้องพื้นกลางห้อง

| 3 | `palette` | **ผ้าที่มีลายและมีสีอย่างน้อย 1 ชิ้น** — ผ้าคลุมลายตาราง หมอนลายดอก พรมทอลาย · ภาพเรานิวทรัลล้วนทั้ง 6 ฉาก **สีตัดหนึ่งจุดคือสิ่งที่ทำให้สายตาหยุด** |

### ⛔ ข้อ 1 ต้องเขียนแบบ "เพิ่ม" ไม่ใช่ "แทน" — ทดสอบแล้วพลาดมาแล้ว

ยิงเทียบกันสองใบด้วยพรอมต์เดียวกัน ต่างแค่การจัดฉาก **ใบที่ใส่โคมไฟกลับได้สีจางลง**
(กลางเฟรม 12.5 เทียบ 15.5) เพราะพอเขียนย่อหน้ายาวเรื่องโคมไฟ **โมเดลตีความว่าฉากมืดลง**
ฟ้าขาวโพลน แสงแบน — **เสียแดดเฉียงที่เป็นตัวทำสีหลักไป**

ในรีลจริงโคมไฟเป็นของ**เพิ่ม** ทั้งสองคลิปที่ทำคะแนนดีเป็นภาพกลางวันเห็นทุ่งเขียวสว่าง
**แล้วค่อยเปิดไฟทับเข้าไป** ไม่ใช่หรี่แสงหลักลงเพื่อให้เห็นไฟ

→ เขียน `lighting` ให้ **ย้ำแสงหลักก่อนแล้วค่อยต่อด้วยโคมไฟ** และระบุว่าแสงหลักยัง**แรงเท่าเดิม**
เช่น `The strong warm raking sunlight is unchanged and still the dominant light in the frame;
in addition, the lamps are switched on.`

### ⛔ อย่าสั่ง "ของบังหน้าเฟรมสร้างระยะ" — ทดลองแล้วพัง ห้ามใส่

เคยเสนอไว้ว่าให้ใส่ขอบประตู/ขอบเสาไว้หน้าเฟรมเพื่อสร้างระยะ **ยิงจริงแล้วโมเดลย้ายกล้อง
ไปยืนในบ้านถ่ายลอดประตูออกมา** — เส้นขอบเดคเลื่อนจาก 78% ลงไปเกือบก้นเฟรม

**นั่นคือการเปลี่ยนจุดยืนกล้อง ซึ่งทำลาย CAMERA LOCK ทั้งใบ** อีกสามเฟสจะอ้างอิงหมุดไม่ได้เลย
และขอบประตูกับฟ้าที่โผล่มายังกินเฟรมด้วยพิกเซลจืดๆ ทำให้ภาพซีดลงอีกต่างหาก

**ความลึกต้องมาจากของที่อยู่ในฉากอยู่แล้ว** (ต้นไม้ระยะหน้า ขอบเดค ก้อนหิน)
ไม่ใช่จากการขยับกล้องไปหลังกรอบอะไรสักอย่าง

> ⚠️ **โคมไฟที่ยึดติดอาคาร (ข้อ 1) ก็เป็นกลุ่ม `fixed` เหมือนกัน** ต้องติดอยู่แล้วตั้งแต่ `phase3.png`
> ไม่ใช่ของที่มาโผล่ใน P4 — วัดจากรีลจริง ไฟผนังสว่างขึ้นตั้งแต่กลางคลิป (10.0 วิ จาก 29 วิ)
> แล้วของที่จัดทีหลังถูกส่องด้วยแสงอุ่นนั้นทั้งหมด
> **โคมไฟตั้งพื้น/ปักดินที่ยกเข้ามาวางได้** ถึงจะเป็น `styling` ของ seg3

**ตรวจด้วยคำสั่ง:** `node tools/check-scene.mjs scenes/<slug> --stage frames`
ด่าน `ภาพจบไม่ซีด (P4)` ต้องได้ `SATAVG ≥ 18` (วัดเฉพาะกลางเฟรม 60%×50%)

⚠️ **SATAVG เป็นตัวชี้ ไม่ใช่ความสวย** ภาพอิ่มสีจัดแต่รกก็ได้คะแนนสูง เป็น WARN ไม่ใช่ FAIL
**ต้องเปิดดูภาพจริงเสมอ** — เคยเจอแล้วว่าใบที่สวยกว่าชัดเจนได้คะแนนต่ำกว่า
เพราะขอบเฟรมกับท้องฟ้าที่จืดเจือค่าเฉลี่ยลง จึงเปลี่ยนมาวัดเฉพาะกลางเฟรม
**ถ้าคะแนนขัดกับสายตา ให้เชื่อสายตา แล้วมาดูว่าตัววัดพลาดตรงไหน**

**สิ่งที่ห้ามลืมในคีย์ `negative`:** `no text, no watermark` — ตัวหนังสือที่ AI วาดเพี้ยนทุกครั้ง
ถ้าอยากได้ตัวหนังสือบนจอ ไปใส่ตอนตัดต่อ ตรงนั้นเป็นฟอนต์จริง ภาษาไทยได้เต็มที่

### 🎯 เกณฑ์ความตรงของสินค้า — "ใกล้เคียง" พอ ไม่ต้อง 100%

**นี่คือกติกาของโปรเจคนี้ ตัดสินไปแล้ว อย่ารื้อ**

สิ่งที่ **ต้องตรง**: ภาพลักษณ์โดยรวม (เป็นของประเภทเดียวกัน วัสดุใกล้กัน โทนสีใกล้กัน)
และ **ฟังก์ชันการทำงาน** (กรุผนัง / แขวน / ตั้งพื้น / พับได้ — ต้องใช้งานแบบเดียวกัน)

สิ่งที่ **ไม่ต้องตรง**: จำนวนสัน จำนวนชั้น จำนวนชิ้น มิติเป๊ะๆ รายละเอียดข้อต่อ
**สินค้าเป็นแค่ตัวอ้างอิง คลิปขายบรรยากาศและผลลัพธ์ ไม่ได้ขายสเปก**

ทำไมกติกานี้ถึงสำคัญ: การไล่ให้สินค้าตรง 100% ทำให้เสียการยิงภาพไปหลายรอบโดยที่คลิปไม่คืบเลย
**ถ้าภาพผ่านเกณฑ์ "ภาพลักษณ์รวม + ฟังก์ชัน" แล้ว ให้รับแล้วเดินต่อทันที**
ผู้ใช้จะบอกเองถ้าอยากได้ตรงกว่านี้

> ยังใส่ตัวเลขที่รู้ลงในคีย์ `product` ได้ตามปกติ มันช่วยให้ผลใกล้ขึ้น
> แต่ **ห้ามใช้ตัวเลขเป็นเกณฑ์ตัดสินรับหรือไม่รับภาพ**

### ⚠️ คีย์ `negative` กันของที่ตีความผิดไม่อยู่ — ต้องแก้ที่ `product` กับ `critical`

วัดมาแล้วจากงานจริง: ใส่ `no acoustic panelling, no thin closely-spaced slats` ครบทุกคำ
แต่ยังได้ฉากกั้นระแนงไม้ตั้งลอยกลับมาแทนแผ่นบอร์ดมีร่อง เพราะ**ชื่อประเภทสินค้าเองลากโมเดล
ไปหาของที่มันคุ้นกว่า** การเติมคำห้ามไปเรื่อยๆ ไม่ช่วย

**ก่อนเขียนคีย์ `product` ให้ถามตัวเองหนึ่งข้อ:**
> *สินค้านี้หน้าตาใกล้กับสินค้าอะไรที่โมเดลเห็นมาเยอะกว่า แล้วสองอย่างนั้นต่างกันตรงไหน*

แล้วเขียน**จุดที่ต่างกันเป็นประโยคบอกเล่า**ลงคีย์ `critical`
ไม่ใช่ไปเพิ่มคำใน `negative` ตัวอย่างที่ใช้ได้จริง:

> *"CRITICAL — this is a CONTINUOUS SOLID SURFACE, not a slat screen. Each panel has a
> solid continuous backing behind the ribs. You CANNOT see through it anywhere.
> The grooves are shallow flat-bottomed channels only 1 cm deep, so the shadow inside
> each groove is a soft narrow band, NOT a deep black void."*

คู่ที่โมเดลสับสนบ่อย: แผ่นระแนงบอร์ด↔ฉากกั้นระแนงไม้ · ชั้นวางติดผนัง↔ชั้นตั้งพื้น ·
ไฟเส้น LED↔ไฟนีออน · หญ้าเทียมแผ่น↔หญ้าจริง · แผ่นกันความร้อน↔ฉนวนใยแก้ว

## ขั้นที่ 4 — พอได้ `phase4.png` แล้ว ต้องทำ `frames/phase4.json` ⭐ ห้ามข้าม

**บัญชีของทุกอย่างที่เห็นในภาพหมุด** — ไม่ใช่ตัวพรอมต์ แต่เป็นเอกสารต้นทางที่พรอมต์อีกสามเฟส
กับตัวตรวจใช้ร่วมกัน **ไม่มีไฟล์นี้ = `check-phase-prompt.mjs` ตรวจอะไรไม่ได้เลย**

**อ่านจากภาพจริง ห้ามลอกจากพรอมต์** พรอมต์คือสิ่งที่เราขอ ภาพคือสิ่งที่ได้จริง สองอย่างนี้ไม่ตรงกันเสมอ

```json
{
  "_about": "บัญชีของทุกอย่างที่เห็นในภาพหมุด frames/phase4.png (<กว้างxสูง>) ใช้เป็นเอกสารต้นทางของพรอมต์ทุกเฟส",
  "_source_image": "frames/phase4.png",
  "pins": [{ "id": "<ชื่อหมุด>", "x": 0.10, "from": 0.22, "to": 0.50, "tol": 2 }],
  "fixed":   [{ "id": "<id>", "name": "<อังกฤษ — สิ่งที่ไม่เปลี่ยนทุกเฟส>", "pos": "<% ที่วัดได้>", "keywords": ["<คำที่พรอมต์ต้องมี>"] }],
  "product": [{ "id": "<id>", "name": "<อังกฤษ — ชิ้นส่วนของสินค้า>", "count": 4, "confidence": "high", "keywords": ["<คำ>"], "covered_by": ["<ชื่อตัวแม่>"], "from_phase": 3 }],
  "styling": [{ "id": "<id>", "name": "<อังกฤษ — ของตกแต่งที่ยกเข้ามาตอน seg3>", "keywords": ["<คำ>"], "covered_by": ["<คำกว้าง>"] }],
  "lighting": { "sun": "<ทิศและเวลา>", "shadows": "<เงาทอดทางไหน>", "keywords": ["sun", "shadow", "light"] },
  "uncertain": ["<สิ่งที่ดูจากภาพแล้วยังไม่แน่ใจ เช่น จำนวนแผ่นหินย่างนับได้ 7-9>"]
}
```

**กติกาที่ทำให้บัญชีนี้ใช้งานได้จริง:**

| คีย์ | ใส่อะไร | ทำไม |
|---|---|---|
| `product` | ชิ้นส่วนของ**สินค้า**ทุกชิ้น | พรอมต์ที่ไม่เอ่ยถึง = **ERROR** โมเดลถือว่าเอาออกได้ (เคยเกิดกับม้านั่งใน P2) |
| `from_phase` | ใส่ให้ชิ้นที่ยัง "ไม่เกิด" ในเฟสนั้น เช่นม้านั่งที่ยังอยู่ในกล่องตอน P2 | ลด ERROR เป็น WARN ให้ใบ P1/P2 |
| `styling` | ของตกแต่งที่**ยกเข้ามาตอน seg3** | ถ้ามันโผล่ในพรอมต์ P1-P3 = **styling-leak** ได้ลำดับเข้า-ออก-เข้า |
| `covered_by` | ชื่อตัวแม่ที่ครอบชิ้นนี้ได้ | ใช้ได้**เฉพาะตอนพรอมต์ปฏิเสธตัวแม่** — `no pavilion` ครอบม้านั่งได้ แต่ `the pavilion is up` ไม่ครอบ |
| `uncertain` | สิ่งที่ดูภาพแล้วยังไม่ชัด | **เขียนว่าไม่แน่ใจ ดีกว่าเดาแล้วให้เฟสอื่นยึดผิด** |

หา `pins` ให้เองด้วยคำสั่งนี้ แล้วก๊อปบรรทัดที่ได้มาใส่:

```bash
node tools/check-scene.mjs scenes/<scene-slug> --probe
```

**เลือกหมุดเฉพาะคอลัมน์ที่ของไม่เปลี่ยนตามเฟส** — คอลัมน์ที่สินค้าไปตั้งอยู่จะอ่านได้ว่าเลื่อน
ทั้งที่กล้องไม่ขยับ เพราะขอบที่แรงที่สุดสลับเส้นไปตามของที่เปลี่ยน

เสร็จแล้วตรวจทั้งด่าน:

```bash
node tools/check-scene.mjs scenes/<scene-slug> --stage frames
```

| ไม่มี `products/<slug>/` | ยังไม่ได้เก็บสินค้า | บอกให้รัน `/aff-timelapse:product` ก่อน **อย่าเดาสินค้า** |
| ไม่มี `design.md` | ไม่รู้ดีไซน์สินค้า | ดูรูปใน `images/main/` แล้วเขียน PRODUCT BLOCK เอง แล้วบอกว่าทำเอง |
| `seeds/` ว่าง | ไม่มีรูป reference สะอาด | ยังเขียนพรอมต์ให้ครบ แต่**เตือนว่าภาพที่ได้อาจไม่เหมือนสินค้าจริง** |
| ผู้ใช้กด Other แล้วพิมพ์โจทย์มา | เขาอยากแก้โจทย์ | คิดใหม่ตามที่เขาบอก แล้วเปิดกล่องเลือกใหม่ อย่าเลือกเอง |

**ห้ามเดาข้อมูลสินค้าและห้ามเลือกไอเดียแทนผู้ใช้** ขั้นที่ 1 ต้องรอผลจากกล่องเลือกจริงๆ
