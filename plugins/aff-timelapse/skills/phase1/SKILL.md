## จังหวะการทำงาน — รายงานแล้วไปต่อเอง

จบขั้นไหน **รายงานผลสั้นๆ 1-3 บรรทัดแล้วทำขั้นถัดไปต่อทันที** ไม่ต้องขออนุญาต
รายงานให้บอก**ผลที่วัดได้** (ได้ไฟล์อะไร กี่รูป ผ่านหรือไม่ผ่าน) ไม่ใช่บอกว่ากำลังจะทำอะไร

**หยุดรอผู้ใช้เฉพาะ 3 กรณีนี้เท่านั้น:**

| หยุดเมื่อ | ตัวอย่าง |
|---|---|
| ต้องให้ผู้ใช้**ตัดสินใจ** | เลือกไอเดีย · รับหรือไม่รับภาพ · จะเขียนทับของเดิมไหม |
| ต้องให้ผู้ใช้**ไปทำเองบนเว็บ** | ยิงภาพหรือวิดีโอที่ Higgsfield |
| **ติดปัญหาที่แก้เองไม่ได้** | Chrome ไม่เชื่อมต่อ · ไม่มีไฟล์ที่ต้องใช้ · คำสั่งที่ต้องใช้ไม่มีในเครื่อง |

นอกจากสามข้อนี้ **ห้ามถามว่า "จะให้ทำต่อไหม"** — ทำต่อได้เลย
ขั้นที่พังไม่ได้แปลว่าต้องหยุดทั้งงาน **ทำขั้นที่เหลือให้จบแล้วค่อยบอกว่าขั้นไหนไม่สำเร็จเพราะอะไร**

สกิลนี้ทำงานบนภาพที่มีอยู่แล้วเท่านั้น ไม่มีภาพก็ไม่มีอะไรให้แก้

> โซ่ที่ใช้จริงคือ **`P4 → P3 → P1 → P2`** ทุกใบแก้จากภาพเดียวในโซ่ ไม่ใช่แก้จาก P4 ทุกใบ
> **เหตุผล:** จาก P4 ต้อง**ลบ**ทั้งของแต่งและตัวสินค้าพร้อมกัน ซึ่งโมเดลทำไม่ไหว มันวาดฉากใหม่แทน
> (วัดแล้วหมุดคลาด 13-20%) ส่วนจาก P3 เหลือแค่ลบตัวสินค้าอย่างเดียว งานเบากว่ามาก
> **และห้ามใส่สองอ้างอิงเด็ดขาด** — สองภาพ = โมเดลสังเคราะห์ฉากใหม่ ไม่ใช่แก้ภาพ
> วัดได้ SSIM โซนนิ่ง 0.312 แย่สุด **ทั้งที่ผ่านหมุดครบทุกเส้น**

> **ทำไมต้องแก้ภาพ ไม่ใช่ gen ใหม่**
> ยิง text-to-image ด้วยพรอมต์เดียวกันเป๊ะทุกตัวอักษร ก็ยังได้กล้องคนละมุม
> โมเดลไม่มีความจำเรื่องตำแหน่งกล้องข้ามการยิงแต่ละครั้ง
> การแก้ภาพเดิมคือทางเดียวที่ผนังจะอยู่ที่เดิม

## ขั้นที่ 1 — แปลงหมุดอ้างอิงเป็นบรรทัด `KEEP EXACTLY AS-IS`

อ่านหมุดอ้างอิงทั้ง 4 ข้อจาก CAMERA LOCK CARD แล้วเขียนใหม่เป็นภาษาอังกฤษ ข้อละ 1 บรรทัด
**ระบุตำแหน่งเป็นตัวเลข** ("at 55% frame height") ไม่ใช่คำลอยๆ ("in the middle")

เพิ่มอีก 2 บรรทัดที่ต้องมีเสมอไม่ว่าฉากไหน:

- ทิศทาง สี และความแข็งของแสง
- สีและพื้นผิวของผนังกับพื้น

## ขั้นที่ 2 — ตัดสินว่าอะไรต้องหายไป และเหลืออะไรแทน

Phase 1 ไม่ใช่แค่ "เอาของออก" มันต้องดูเหมือนพื้นที่ที่ **ยังไม่เคยถูกแตะต้อง**

| เอาออก | ใส่แทน |
|---|---|
| สินค้าและของตกแต่งทุกชิ้น | พื้นเปล่าๆ มีฝุ่นบาง มีรอยครูดจางๆ |
| ต้นไม้ พรม หมอน โคมไฟ | ผนังโล่ง ไม่มีอะไรติด ไม่มีรูสกรู |
| ของจัดฉากทุกอย่าง | พื้นที่ที่ดูไม่มีใครใช้ ไม่มีใครดูแล |

**เพิ่มร่องรอยความ "ยังไม่ได้ทำ" อย่างน้อย 1 อย่าง** — คราบน้ำจางๆ · สีผนังซีดไม่เท่ากัน ·
ใบไม้แห้งกองมุม · กระถางเปล่าที่แตกแล้ว — อันนี้คือสิ่งที่ทำให้ before/after จี๊ด
แต่ **ห้ามใส่จนดูเป็นบ้านร้าง** มันต้องเป็นบ้านที่มีคนอยู่ แค่ยังไม่ได้จัดมุมนี้

> ⚠️ **โซนวางสินค้าต้องโล่งสนิท** ตามที่ระบุใน CAMERA LOCK CARD
> ถ้าตรงนั้นมีของอื่นอยู่ คนดูจะอ่านว่า "ของเดิมหายไป" แทน "ของใหม่ถูกเพิ่มเข้ามา"

### ⭐ P1 ต้องอ่านว่า "กำลังจะทำ" ไม่ใช่ "ห้องร้าง" (ของใหม่ 1.15.0)

**ใส่ร่องรอยการวางแผน 1-2 อย่างตรงโซนที่สินค้าจะไปอยู่** — เทปกาวตีเส้นบนพื้น · รอยชอล์ก ·
ตลับเมตรวางทิ้งไว้ · กระดาษแบบพับวางที่พื้น · ดินสอช่างวางข้างๆ

ถอดจากกฎ **ZERO-CONSTRUCTION START LOCK** ของมาสเตอร์พรอมต์งานก่อสร้าง ซึ่งบังคับให้ภาพแรก
มี *"white powder layout marking only, workers marking layout, no excavation yet"*
ที่ดินยังไม่ถูกแตะ **แต่เห็นชัดว่ากำลังจะเกิดอะไรขึ้น**

P1 ของเราเดิมเป็นแค่ "ว่างเปล่า + ทรุดโทรม" ซึ่ง**ไม่มีสัญญาณว่ามีอะไรกำลังจะมา** —
เป็นภาพที่คนดูเลื่อนผ่านได้ ร่องรอยการวางแผนคือสิ่งที่ทำให้ 3 วิแรกมีคำถามค้างในหัว

⛔ **ห้ามมีวัสดุหรือชิ้นส่วนของสินค้าอยู่ในเฟรม** — นั่นคือ P2 แล้ว
เส้นที่แบ่งคือ **"วางแผนไว้" กับ "ของมาถึงแล้ว"**

⚠️ **ร่องรอยพวกนี้อยู่บนพื้น ซึ่งปกติอยู่นอก `static_band` (ปริยายบน 40%)**
แต่ **ต้องยืนยันด้วย `probe-band` ต่อฉาก อย่าเหมาว่าปลอดภัย** — ฉากที่โซนวัดกินลงมาถึงพื้น
จะโดนด่าน SSIM ทันที ถ้าเจอให้เว้นโซนด้วย `static_band` หลายกล่อง ไม่ใช่ถอดร่องรอยออก

## ขั้นที่ 3 — เขียนไฟล์ (พรอมต์เป็น JSON เท่านั้น)

> ⛔ **พรอมต์แก้ภาพที่ยาวเกินและมีคำสั่งห้ามเยอะ จะ Generation failed ไปเลย ไม่ใช่แค่ผลไม่ดี**
> วัดมาแล้ว: โครง `KEEP EXACTLY AS-IS` / `REMOVE COMPLETELY` / `REPLACE WITH` / `NEGATIVE`
> ยาว ~2,000 ตัวอักษร พร้อมพิกัด % ทุกเส้น **ยิงแล้ว failed ทั้งสองใบ ไม่มีภาพออกมาเลย**
> พอตัดเหลือครึ่งเดียวและเขียนเป็นประโยคบอกเล่าล้วน **ผ่านทันทีในรอบเดียว**
>
> **กติกา: ไม่เกิน ~1,200 ตัวอักษร · บรรยายสภาพปลายทางเป็นประโยคบอกเล่า
> ไม่ใช่สั่งว่าห้ามอะไร · ห้ามใส่พิกัด % · JSON กินเพิ่มราว 70-100 ตัวอักษร เผื่อไว้ตอนนับ**

**ค่าในทุกคีย์เขียนเป็นภาษาอังกฤษ** — คำอธิบายกับหัวข้อรอบๆ เป็นไทยได้ แต่ตัวพรอมต์ที่ส่งเข้าโมเดล
ต้องเป็นอังกฤษ สถิติที่วัดมาทั้งหมดมาจากพรอมต์อังกฤษ **และเนื้อในแต่ละคีย์ต้องเป็นประโยคบอกเล่า
ไม่ใช่คำสั่งห้ามเรียงกัน**

## ขั้นสุดท้าย — ส่งมอบ

1. **วางพรอมต์ในกล่องโค้ดให้ก๊อปได้ทันที** พร้อมบอกผลตรวจจากขั้นที่ 4 (ERROR 0 · leak 0)
2. ย้ำว่าต้อง**ใส่ `frames/phase3.png` เป็นภาพตั้งต้น รูปเดียว** ไม่ใช่ยิงเปล่า และ**ห้ามใส่รูปที่สอง**
3. บอกว่า **ยิงเสร็จบนเว็บแล้วบอกได้เลย ไม่ต้องเซฟไฟล์เอง** —
   ดึงด้วย Higgsfield MCP `show_generations` แล้วโหลด `results.rawUrl`
   (ไม่ใช่ `minUrl` ซึ่งเป็น webp ย่อ) ลง `scenes/<scene-slug>/frames/phase1.png`
   **การอ่านผ่าน MCP ไม่กินเครดิต** มีแต่การยิงที่กิน · ยืนยันว่า `params.prompt`
   ตรงกับพรอมต์ที่ส่งไปจริงก่อนโหลดเสมอ
4. **บอกวิธีตรวจทันทีที่ได้ภาพ** — เปิด phase1 กับ phase3 สลับไปมาเร็วๆ
   ขอบผนัง ขอบหน้าต่าง และเส้นขอบฟ้า **ต้องไม่กระดิก** ถ้าขยับ = ยิงใหม่
   อย่าปล่อยผ่าน เพราะขั้นวิดีโอแก้ไม่ได้แล้ว
   แล้วรัน `node tools/check-scene.mjs scenes/<slug> --stage frames` —
   ด่าน **`องค์ประกอบโซนที่ห้ามเปลี่ยน`** วัด SSIM ให้ว่าใบนี้ยังเป็นฉากเดียวกับต้นทางไหม
   **หมุดตรงอย่างเดียวไม่พอ** ใบที่วาดฉากใหม่เคยผ่านหมุดครบทุกเส้นมาแล้ว

| เจออะไร | แปลว่า | ทำยังไงต่อ |
|---|---|---|
| ไม่มี `frames/phase3.png` | โซ่ยังมาไม่ถึง | หยุด บอกให้ทำ Phase 3 ก่อน **ห้ามเขียนพรอมต์สร้างภาพใหม่แทน และห้ามใช้ phase4.png แทน** |
| ไม่มี `scene.md` | ไม่มี CAMERA LOCK | บอกให้รัน `/aff-timelapse:idea` ก่อน |
| ยิงแล้วมุมเลื่อน | พรอมต์ล็อกกล้องแรงไม่พอ | เพิ่มหมุดอ้างอิงให้ละเอียดขึ้น ระบุ % ตำแหน่งให้ครบ แล้วยิงใหม่ **อย่ายอมรับภาพที่มุมเลื่อน** |
| ยิงแล้วของหายไม่หมด | ท่อน REMOVE รวบรัดไป | เรียกชื่อของที่เหลือทีละชิ้นแล้วยิงซ้ำจากภาพเดิม |

**ห้ามเขียนพรอมต์ที่เป็น text-to-image ในสกิลนี้** — ทั้งหมดต้องเป็นพรอมต์แก้ภาพเท่านั้น
