## ก่อนเริ่ม — เช็ค 2 อย่าง

1. `scenes/<scene-slug>/scene.md` มีอยู่ และมีบล็อก `=== CAMERA LOCK ===`
2. `scenes/<scene-slug>/frames/phase4.png` **มีอยู่จริง**

ถ้าไม่มีข้อ 2 ให้บอกผู้ใช้ว่ายังไม่ได้ยิงภาพ Phase 4 แล้วหยุด —
สกิลนี้ทำงานบนภาพที่มีอยู่แล้วเท่านั้น ไม่มีภาพก็ไม่มีอะไรให้แก้

> **ทำไมต้องแก้ภาพ ไม่ใช่ gen ใหม่**
> ยิง text-to-image ด้วยพรอมต์เดียวกันเป๊ะทุกตัวอักษร ก็ยังได้กล้องคนละมุม
> โมเดลไม่มีความจำเรื่องตำแหน่งกล้องข้ามการยิงแต่ละครั้ง
> การแก้ภาพเดิมคือทางเดียวที่ผนังจะอยู่ที่เดิม

## ขั้นที่ 1 — แปลงหมุดอ้างอิงเป็นบรรทัด `KEEP EXACTLY AS-IS`

อ่านหมุดอ้างอิงทั้ง 4 ข้อจาก CAMERA LOCK CARD แล้วเขียนใหม่เป็นภาษาอังกฤษ ข้อละ 1 บรรทัด
**ระบุตำแหน่งเป็นตัวเลข** ("at 55% frame height") ไม่ใช่คำลอยๆ ("in the middle")

เพิ่มอีก 2 บรรทัดที่ต้องมีเสมอไม่ว่าฉากไหน:

- ทิศทาง สี และความแข็งของแสง
- สีและพื้นผิวของผนังกับพื้น

## ขั้นที่ 2 — ตัดสินว่าอะไรต้องหายไป และเหลืออะไรแทน

Phase 1 ไม่ใช่แค่ "เอาของออก" มันต้องดูเหมือนพื้นที่ที่ **ยังไม่เคยถูกแตะต้อง**

| เอาออก | ใส่แทน |
|---|---|
| สินค้าและของตกแต่งทุกชิ้น | พื้นเปล่าๆ มีฝุ่นบาง มีรอยครูดจางๆ |
| ต้นไม้ พรม หมอน โคมไฟ | ผนังโล่ง ไม่มีอะไรติด ไม่มีรูสกรู |
| ของจัดฉากทุกอย่าง | พื้นที่ที่ดูไม่มีใครใช้ ไม่มีใครดูแล |

**เพิ่มร่องรอยความ "ยังไม่ได้ทำ" อย่างน้อย 1 อย่าง** — คราบน้ำจางๆ · สีผนังซีดไม่เท่ากัน ·
ใบไม้แห้งกองมุม · กระถางเปล่าที่แตกแล้ว — อันนี้คือสิ่งที่ทำให้ before/after จี๊ด
แต่ **ห้ามใส่จนดูเป็นบ้านร้าง** มันต้องเป็นบ้านที่มีคนอยู่ แค่ยังไม่ได้จัดมุมนี้

> ⚠️ **โซนวางสินค้าต้องโล่งสนิท** ตามที่ระบุใน CAMERA LOCK CARD
> ถ้าตรงนั้นมีของอื่นอยู่ คนดูจะอ่านว่า "ของเดิมหายไป" แทน "ของใหม่ถูกเพิ่มเข้ามา"

## ขั้นที่ 3 — เขียนไฟล์ (ใช้โครง 5 บรรทัดนี้เท่านั้น)

> ⛔ **พรอมต์แก้ภาพที่ยาวเกินและมีคำสั่งห้ามเยอะ จะ Generation failed ไปเลย ไม่ใช่แค่ผลไม่ดี**
> วัดมาแล้ว: โครง `KEEP EXACTLY AS-IS` / `REMOVE COMPLETELY` / `REPLACE WITH` / `NEGATIVE`
> ยาว ~2,000 ตัวอักษร พร้อมพิกัด % ทุกเส้น **ยิงแล้ว failed ทั้งสองใบ ไม่มีภาพออกมาเลย**
> พอตัดเหลือครึ่งเดียวและเขียนเป็นประโยคบอกเล่าล้วน **ผ่านทันทีในรอบเดียว**
>
> **กติกา: ไม่เกิน ~1,200 ตัวอักษร · บรรยายสภาพปลายทางเป็นประโยคบอกเล่า
> ไม่ใช่สั่งว่าห้ามอะไร · ห้ามใส่พิกัด %**

````markdown
# Phase 1 — ว่างเปล่า / ก่อนรีโนเวท

ยิงที่ Higgsfield เว็บ · **โหมดแก้ภาพ ใส่ `frames/phase4.png` เป็นภาพตั้งต้น** · 9:16

```
Reference Image 1. Same <ชนิดพื้นที่>, same camera angle and position.

Scene: The same <พื้นที่> before any renovation. <บรรยายพื้นผิวเปล่าที่ควรเห็นแทน
+ ร่องรอยความยังไม่ได้ทำ 1-2 อย่าง> <ระบุสิ่งที่ไม่เปลี่ยน: unchanged>

Subject: An empty unused <พื้นที่> that nobody has decorated yet. No people, no
furniture, no plants, no <สินค้า>.

Camera: Exact same static wide-angle position as Image 1, same <ชนิดเพอร์สเปกทีฟ>,
same framing, 9:16 vertical composition. <หมุดอ้างอิง 3-4 อย่าง เขียนต่อกันเป็น
ประโยคเดียว> all stay in exactly the same place.

Lighting: Same <ทิศและช่วงเวลาแสง>, same <เงาเด่นๆ ที่ต้องคงไว้>.

Style: Photorealistic, architectural documentation photography, before-renovation
stage.
```
````

**สิ่งที่เปลี่ยนจากของเดิมและทำไม:**

| เดิม (พัง) | ใหม่ (ผ่าน) |
|---|---|
| `Edit the attached image. Do not... Do not...` | `Reference Image 1. Same X, same camera angle and position.` |
| ลิสต์หมุดทีละบรรทัดพร้อมพิกัด % | รวมหมุดเป็นประโยคเดียวในบรรทัด `Camera:` ไม่ใส่ % |
| บล็อก `REMOVE COMPLETELY` ไล่ชื่อของ | บรรยายสภาพปลายทางว่าไม่มีอะไรอยู่ ใน `Scene:` กับ `Subject:` |
| บล็อก `NEGATIVE:` ยาวเป็นพรืด | คำว่า `No people, no furniture, no plants` สั้นๆ ในบรรทัด `Subject:` |

**ยังต้องมีหมุดอ้างอิงอยู่** แค่ย้ายไปอยู่ในบรรทัด `Camera:` เป็นประโยคเดียว
เช่น *"The balcony soffit edge, the railing handrail, the city skyline and the floor
grout lines all stay in exactly the same place."* — ได้ผลดีพอๆ กับลิสต์ยาว แต่ไม่ทำให้ failed

## ขั้นสุดท้าย — ส่งมอบ

1. **วางพรอมต์ในกล่องโค้ดให้ก๊อปได้ทันที**
2. ย้ำว่าต้อง**ใส่ `frames/phase4.png` เป็นภาพตั้งต้น** ไม่ใช่ยิงเปล่า
3. บอกว่า **ยิงเสร็จบนเว็บแล้วบอกได้เลย ไม่ต้องเซฟไฟล์เอง** —
   ดึงด้วย Higgsfield MCP `show_generations` แล้วโหลด `results.rawUrl`
   (ไม่ใช่ `minUrl` ซึ่งเป็น webp ย่อ) ลง `scenes/<scene-slug>/frames/phase1.png`
   **การอ่านผ่าน MCP ไม่กินเครดิต** มีแต่การยิงที่กิน · ยืนยันว่า `params.prompt`
   ตรงกับพรอมต์ที่ส่งไปจริงก่อนโหลดเสมอ
4. **บอกวิธีตรวจทันทีที่ได้ภาพ** — เปิด phase1 กับ phase4 สลับไปมาเร็วๆ
   ขอบผนัง ขอบหน้าต่าง และเส้นขอบฟ้า **ต้องไม่กระดิก** ถ้าขยับ = ยิงใหม่
   อย่าปล่อยผ่าน เพราะขั้นวิดีโอแก้ไม่ได้แล้ว
5. คำสั่งถัดไป: `/aff-timelapse:phase2 <scene-slug>`

## กฎเหล็ก

| เจออะไร | แปลว่า | ทำยังไงต่อ |
|---|---|---|
| ไม่มี `frames/phase4.png` | ยังไม่ได้ยิงภาพหมุด | หยุด บอกให้ยิง Phase 4 ก่อน **ห้ามเขียนพรอมต์สร้างภาพใหม่แทน** |
| ไม่มี `scene.md` | ไม่มี CAMERA LOCK | บอกให้รัน `/aff-timelapse:idea` ก่อน |
| ยิงแล้วมุมเลื่อน | พรอมต์ล็อกกล้องแรงไม่พอ | เพิ่มหมุดอ้างอิงให้ละเอียดขึ้น ระบุ % ตำแหน่งให้ครบ แล้วยิงใหม่ **อย่ายอมรับภาพที่มุมเลื่อน** |
| ยิงแล้วของหายไม่หมด | ท่อน REMOVE รวบรัดไป | เรียกชื่อของที่เหลือทีละชิ้นแล้วยิงซ้ำจากภาพเดิม |

**ห้ามเขียนพรอมต์ที่เป็น text-to-image ในสกิลนี้** — ทั้งหมดต้องเป็นพรอมต์แก้ภาพเท่านั้น
