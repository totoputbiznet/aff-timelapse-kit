## จังหวะการทำงาน — รายงานแล้วไปต่อเอง

จบขั้นไหน **รายงานผลสั้นๆ 1-3 บรรทัดแล้วทำขั้นถัดไปต่อทันที** ไม่ต้องขออนุญาต
รายงานให้บอก**ผลที่วัดได้** (ได้ไฟล์อะไร กี่รูป ผ่านหรือไม่ผ่าน) ไม่ใช่บอกว่ากำลังจะทำอะไร

**หยุดรอผู้ใช้เฉพาะ 3 กรณีนี้เท่านั้น:**

| หยุดเมื่อ | ตัวอย่าง |
|---|---|
| ต้องให้ผู้ใช้**ตัดสินใจ** | เลือกไอเดีย · รับหรือไม่รับภาพ · จะเขียนทับของเดิมไหม |
| ต้องให้ผู้ใช้**ไปทำเองบนเว็บ** | ยิงภาพหรือวิดีโอที่ Higgsfield |
| **ติดปัญหาที่แก้เองไม่ได้** | Chrome ไม่เชื่อมต่อ · ไม่มีไฟล์ที่ต้องใช้ · คำสั่งที่ต้องใช้ไม่มีในเครื่อง |

นอกจากสามข้อนี้ **ห้ามถามว่า "จะให้ทำต่อไหม"** — ทำต่อได้เลย
ขั้นที่พังไม่ได้แปลว่าต้องหยุดทั้งงาน **ทำขั้นที่เหลือให้จบแล้วค่อยบอกว่าขั้นไหนไม่สำเร็จเพราะอะไร**

## ขั้นที่ 1 — เก็บข้อมูลกับรูป

ทำตาม `${CLAUDE_SKILL_DIR}/../../references/shopee-collect.md` **ทั้ง 5 ขั้น**
(เปิด Chrome จริง · สโคปจาก container ของแกลเลอรี · ห้ามเรียก Shopee API · โหลดรูปด้วย `fetch-images.mjs`)

> ⛔ **เลื่อนหน้าช้าๆ** Shopee จับความเร็วการเลื่อน ไม่ใช่แค่การเรียก API
> การยิง `scrollBy` ติดกันรัวๆ ใน `javascript_tool` จะเด้งไปหน้า `/verify/captcha` แล้วเสียหน้าสินค้าทั้งแท็บ
> **เลื่อนทีละไม่เกิน 10 tick แล้วรออย่างน้อย 1 วินาที** และเลื่อนเท่าที่จำเป็นเท่านั้น
> เจอหน้า verify แล้วให้ `navigate` กลับเข้าหน้าสินค้าใหม่ **อย่าเลื่อนซ้ำแบบเดิม**
>

> → (ค่อยลอง) รูปโซนรายละเอียด เพราะโซนรายละเอียดต้องเลื่อนเยอะที่สุดและเสี่ยงที่สุด
> ถ้าโดนบล็อกตอนเก็บโซนรายละเอียด **ไม่ต้องเสียเวลาลองใหม่** รูปโซนนั้นเกือบทั้งหมดมีตัวหนังสือแปะอยู่แล้ว
> ใช้เป็น reference ไม่ได้ ให้ระบุในสรุปว่าข้ามเพราะโดนกันบอท


## ขั้นที่ 2 — คัดรูปสะอาดลง `seeds/`

รูปที่จะเอาไปเป็น reference ให้โมเดลสร้างภาพ **ต้องไม่มี 3 อย่างนี้เด็ดขาด**:

- ตัวหนังสือทุกชนิด (ป้ายสเปก ป้าย "ส่งฟรี" ข้อความบนรูป)
- ลายน้ำหรือโลโก้ร้าน
- คนหรือมือที่ถือสินค้าอยู่

เปิดรูปดูด้วยตาแล้วก๊อปเฉพาะรูปที่ผ่านไปไว้ที่ `seeds/` ตั้งชื่อ `seed-01.jpg` ไล่ไป
**เอารูปที่เห็นสินค้าเต็มตัวจากมุมเฉียงเป็นอันดับแรก** มันบอกรูปทรงได้ดีที่สุด

### ถ้าคัดแล้วเหลือ 0 รูป — ยังไม่ต้องยอมแพ้ ให้ครอปก่อน ⭐

**นี่คือกรณีปกติ ไม่ใช่กรณียกเว้น** ร้านไทยส่วนใหญ่แปะตัวหนังสือทับทุกรูปในแกลเลอรี
แต่รูปพวกนั้นมักมี **โซนภาพสินค้าสะอาดอยู่ข้างใน** — รูปสเปก/พารามิเตอร์คือที่ที่เจอบ่อยที่สุด
เพราะมันมักเป็นสินค้าวางบนพื้นเทาหรือพื้นขาว มีหัวข้อเป็นตัวหนังสืออยู่ด้านบนเฉยๆ

ไล่หาตามนี้ **ก่อน**จะสรุปว่าไม่มีรูปใช้ได้:

1. เปิดรูปดูทีละใบ หาโซนสี่เหลี่ยมที่มีแต่ตัวสินค้า ไม่มีตัวหนังสือคาบเกี่ยว
2. ครอปโซนนั้นออกมา แล้วขยายกลับให้คมด้วย LANCZOS

```
python -c "from PIL import Image; im=Image.open(r'<ไฟล์ต้นทาง>'); im.crop((<l>,<t>,<r>,<b>)).resize((<w*2>,<h*2>), Image.LANCZOS).save(r'products/<slug>/seeds/seed-01.jpg', quality=95)"
```

3. **เปิดไฟล์ที่ครอปแล้วดูซ้ำ** ว่าไม่มีตัวหนังสือหลงเหลือแม้แต่ตัวเดียว
4. รูปที่มีแบบเทคนิค/แบบหน้าตัดพร้อมมิติ ให้ครอปเก็บไว้เป็น `ref-<ชื่อ>.jpg` ด้วย
   **ไม่ใช่เพื่อใช้เป็น reference ภาพ** แต่เพื่ออ่านตัวเลขไปเขียน `design.md` ในขั้นที่ 3
   ตัวเลขจากแบบเทคนิคแม่นกว่าการนับจากรูปถ่ายเสมอ

ถ้าครอปแล้วยัง**ไม่มีโซนสะอาดจริงๆ** ค่อยบอกผู้ใช้ตรงๆ ว่าไม่มีรูปที่ใช้เป็น reference ได้
**อย่าฝืนใช้รูปที่มีตัวหนังสือ** โมเดลจะลอกตัวหนังสือติดมาในภาพที่ gen ออกมาด้วย

## ขั้นที่ 3 — ให้ ChatGPT อ่านดีไซน์จากรูป → `design.md` ⭐

**ขั้นนี้สำคัญที่สุดของสกิล** พิสูจน์มาแล้วจากงานเดิมว่ารูป reference อย่างเดียวไม่พอ —
โมเดลสร้างภาพจะอ่านโครงสร้างผิด ต้องมีคำบรรยายเป็นตัวหนังสือกำกับคู่กันไปเสมอ

```
printf '%s' "ดูรูปที่แนบมา บรรยายดีไซน์ของสินค้าให้ละเอียดเป็นภาษาไทย เฉพาะสิ่งที่เห็นจริง เน้นรูปทรงโครงสร้าง จำนวนชั้นหรือชิ้นส่วนที่นับได้ วัสดุ สีและผิวสัมผัส ขาหรือฐานรองรับ บานพับหรือข้อต่อที่มองเห็น และสิ่งที่ทำให้รุ่นนี้ต่างจากรุ่นทั่วไปในท้องตลาด บอกด้วยว่าสินค้านี้ควรวางกับพื้น แขวนผนัง หรือตั้งบนโต๊ะ ห้ามบรรยายตัวหนังสือหรือลายน้ำ ตอบเป็นย่อหน้าเดียวไม่เกิน 6 บรรทัด ไม่ต้องสร้างไฟล์" | codex exec --skip-git-repo-check -i products/<slug>/seeds/seed-01.jpg -
```

> ⚠️ `-i` รับหลายไฟล์ **ห้ามวางพรอมต์เป็นอาร์กิวเมนต์ต่อท้าย** ต้องส่งทาง stdin แล้วปิดด้วย `-`

**ถ้ามีไฟล์ `ref-*.jpg` ที่เป็นแบบเทคนิค ให้แนบไปด้วย** (`-i` รับหลายไฟล์)
แล้ว**เชื่อตัวเลขจากแบบเทคนิคก่อนเสมอ** เวลาที่มันขัดกับสิ่งที่ codex นับจากรูปถ่าย —
การนับสัน/ชิ้นส่วนจากภาพเป็นสิ่งที่โมเดลพลาดบ่อยที่สุด

เซฟผลลง `design.md` โดยมี 3 หัวข้อ:

```markdown
# ดีไซน์ตามที่เห็นในรูป — <ชื่อสินค้า>

## คำบรรยาย (ไทย)
<ผลจาก codex>

## PRODUCT BLOCK (อังกฤษ — ก๊อปไปวางในพรอมต์ได้เลย)
<แปลเป็นอังกฤษ เขียนเป็นวลีต่อเนื่อง ระบุจำนวนที่นับได้เป็นตัวเลข>

## ลำดับติดตั้งจริง (INSTALL SEQUENCE)
1. <ขั้นแรกจริงๆ ของสินค้าชนิดนี้>
2. <ขั้นถัดไป — เรียงตามที่ช่างทำจริง ไม่ใช่ตามที่เล่าแล้วสวย>
3. ...
- **เครื่องมือที่ต้องเห็นในเฟรม:** <สว่าน · ระดับน้ำ · ค้อนยาง · คัตเตอร์>
- **ขั้นที่มีจังหวะซ้ำได้** (ที่โคลสอัพจะไปเกาะ): <ข้อไหน>
- **อะไรต้องมีก่อนอะไรถึงจะอยู่ได้:** <เช่น แผ่นตั้งเองไม่ได้ก่อนโครงเคร่าขึ้น>
```

**PRODUCT BLOCK ต้องนับได้** — เขียน `7 horizontal slats on the backrest` ไม่ใช่ `several slats`
ตัวเลขคือสิ่งเดียวที่ทำให้โมเดลวาดสินค้าออกมาเหมือนเดิมทุกครั้ง

### ⭐ INSTALL SEQUENCE — ห้าม hard-code ลำดับเดียวใช้ทุกสินค้า (ของใหม่ 1.15.0)

ถอดจากกฎ **ADAPTIVE STRUCTURAL DISTRIBUTION** ของมาสเตอร์พรอมต์งานก่อสร้าง ซึ่งบังคับว่า
ลำดับต้องตรงกับ**ระบบวัสดุจริง** (RCC / โครงไม้ / ไฮบริด) และ *"ห้าม hard-code เสาปูนถ้าเป็นบ้านไม้"*

ลำดับ A/B/C ในสกิล `storyboard` เป็นลำดับ**ทั่วไป** (เตรียมพื้นที่ → ลงพื้น → งานยึดติด → จัดของ)
**ยังไม่ผูกกับวิธีติดตั้งจริงของสินค้าแต่ละชนิด** ซึ่งต่างกันจริง:

| สินค้า | ลำดับจริง |
|---|---|
| **แผ่นระแนงผนัง** | วัดระยะ+ตีเส้น → ตีโครงเคร่า → ติดแผ่นทีละแผ่น → เก็บขอบ/บัว |
| **เดคปูพื้น** | ปรับพื้นให้เรียบ → รองพื้น/แผ่นกันความชื้น → วางแผ่นจากมุมไล่ออก → ตัดขอบ → เก็บขอบ |
| **ฉากกั้นตั้งพื้น** | วัดระยะ → ยึดฐาน/ขายึด → ตั้งเสาทีละต้น → ใส่แผ่นระหว่างเสา → ปรับระดับ |

`phase2` ใช้ไฟล์นี้ตัดสินว่า **P2 ควรค้างอยู่ขั้นไหน** · `storyboard` ใช้เรียง `Action:` และ
ตรวจกฎข้อ 10 (ห้ามของค้ำตัวเอง) **ถ้าไม่มีบล็อกนี้ ทั้งสองสกิลจะเดาลำดับเอง**

⛔ **เขียนจากรูปจริงกับหน้า Shopee เท่านั้น ดูไม่ออกให้เขียนว่าดูไม่ออก ห้ามเดา**
กฎเดียวกับ PRODUCT BLOCK — **ลำดับที่เดาผิดแย่กว่าไม่มีลำดับ** เพราะสองสกิลจะยึดตามโดยไม่รู้ว่าผิด

### ⛔ ห้ามนับชิ้นส่วนจากรูปแบนใบเดียว — กฎที่แพงที่สุดในสกิลนี้

วัดมาแล้วจากงานจริง: นับสันแผ่นระแนงจากรูปแผ่นวางแบนใบเดียว ได้ *5 สัน ร่องตื้นบนแผ่นตัน*
ของจริงคือ **4 กล่องกลวงตั้งขึ้นจากแผ่นฐานบาง ร่องลึกเกือบเท่าความหนาแผ่น** — ผิดทั้งจำนวนและโครงสร้าง
ความผิดนี้ไหลต่อไปทุกขั้น ทำให้ยิงภาพเสียไป 3 รอบกว่าจะจับได้

**ก่อนเขียนตัวเลขลง PRODUCT BLOCK ต้องมีอย่างน้อยหนึ่งอย่างนี้ยืนยัน:**

1. **รูปหน้าตัดหรือด้านข้างจริง** — ไล่ดูรูปในโฟลเดอร์ให้ครบทุกใบ ไม่ใช่แค่ใบแรก
   รูปเปรียบเทียบ "ของเรา vs เจ้าอื่น" กับรูป "จุดเด่นสินค้า" มักมีภาพหน้าตัดระยะใกล้ซ่อนอยู่
2. **แบบเทคนิคพร้อมมิติ** — มักอยู่ในรูปสเปก/พารามิเตอร์
3. ถ้าไม่มีทั้งสองอย่าง **ให้เขียนว่าไม่รู้ ห้ามเดา** แล้วบอกผู้ใช้ว่าตัวเลขไหนยังไม่ยืนยัน

**ถ้าสองแหล่งขัดกัน ให้เชื่อแบบเทคนิค** แล้วเขียนกำกับไว้ว่าเชื่ออะไรเพราะอะไร

### รูปที่จะแนบเป็น reference ต้องมีหลายใบจากหลายมุม

ใบเดียวไม่พอ **อย่างน้อยควรมี: รูปเห็นทั้งชิ้น + รูปหน้าตัด/ด้านข้าง + รูประยะใกล้ของจุดเด่น**
เก็บเป็น `seed-01.jpg` `seed-02-<มุม>.jpg` `seed-03-<มุม>.jpg` ตั้งชื่อบอกว่าเป็นมุมอะไร

**แต่คัดสองอย่างนี้ออกก่อนเสมอ:**

| ห้ามแนบ | เพราะ |
|---|---|
| รูปแบบเทคนิคที่มีตัวเลขกำกับ | โมเดลลอกตัวเลขมาวาดเป็นอักษรบิดเบี้ยว — เก็บไว้ให้**คน**อ่าน ไม่ใช่ให้โมเดลดู |
| รูปตัวอย่างการใช้งานจากหน้าร้านที่**ขัดกับสินค้าจริง** | ร้านมักเอาภาพสต็อกของสินค้าใกล้เคียงมาลง ถ้าแนบไป มันจะไปตอกย้ำความเข้าใจผิดที่เรากำลังแก้อยู่พอดี |

ถ้า `codex` เรียกไม่ได้ ให้**เขียน design.md เองจากการดูรูปกับข้อมูลบนหน้าเว็บ** แล้วระบุในสรุปว่า
ทำเองเพราะเรียก codex ไม่ได้ — อย่าข้ามไฟล์นี้ไปเฉยๆ เพราะขั้นถัดไปต้องใช้

## กฎเหล็ก — ห้ามล้มทั้งงาน

แต่ละขั้นพังได้อิสระจากกัน **ทำขั้นที่เหลือต่อให้จบเสมอ** แล้วบอกว่าขั้นไหนไม่สำเร็จเพราะอะไร

| เจออะไร | แปลว่า | ทำยังไงต่อ |
|---|---|---|
| Chrome ไม่เชื่อมต่อ | ไม่มีเบราว์เซอร์ให้ใช้ | หยุดแล้วบอกตรงๆ **อย่าเดาข้อมูลสินค้า** |
| หน้าเด้งไป verify | โดนกันบอท | navigate กลับเข้าหน้าสินค้าใหม่ ห้ามเรียก API ซ้ำ |
| เก็บรูปไม่ได้เลย | โหลดรูปพัง | ยังส่ง `product.md` ให้ครบ แล้วบอกว่าต้องหารูปมาเองก่อนไปขั้น `idea` |
| หน้าเด้งไป `/verify/captcha` | เลื่อนหน้าเร็วเกิน | `navigate` กลับเข้าหน้าสินค้า **ห้ามเลื่อนซ้ำแบบเดิม** ทำต่อจากข้อมูลที่เก็บมาแล้ว |
| รูปมีตัวหนังสือทุกใบ | ปกติของร้านไทย | **ครอปโซนสะอาดออกมาก่อน** (ขั้นที่ 2) อย่าเพิ่งสรุปว่าไม่มีรูปใช้ได้ |
| ครอปแล้วยังไม่มีโซนสะอาด | ไม่มี reference จริงๆ | บอกผู้ใช้ **อย่าฝืนใช้รูปที่มีตัวหนังสือ** ขอให้ถ่ายเองหรือหาแหล่งอื่น |
| `codex` ไม่มีหรือล็อกอินไม่ได้ | ไม่มีตัวอ่านดีไซน์ | เขียน `design.md` เองจากรูป แล้วระบุว่าทำเอง |

**ห้ามแต่งข้อมูลสินค้าขึ้นเองในทุกกรณี** — อ่านหน้าเว็บไม่ได้ให้บอกว่าอ่านไม่ได้
**ลิงก์ที่บันทึกต้องเป็นลิงก์เดิมที่ผู้ใช้ให้มา** (มีรหัสติดตามแอฟฟิลิเอตอยู่ ห้ามตัดทิ้ง)
