## จังหวะการทำงาน — รายงานแล้วไปต่อเอง

จบขั้นไหน **รายงานผลสั้นๆ 1-3 บรรทัดแล้วทำขั้นถัดไปต่อทันที** ไม่ต้องขออนุญาต
รายงานให้บอก**ผลที่วัดได้** (ได้ไฟล์อะไร กี่รูป ผ่านหรือไม่ผ่าน) ไม่ใช่บอกว่ากำลังจะทำอะไร

**หยุดรอผู้ใช้เฉพาะ 3 กรณีนี้เท่านั้น:**

| หยุดเมื่อ | ตัวอย่าง |
|---|---|
| ต้องให้ผู้ใช้**ตัดสินใจ** | เลือกไอเดีย · รับหรือไม่รับภาพ · จะเขียนทับของเดิมไหม |
| ต้องให้ผู้ใช้**ไปทำเองบนเว็บ** | ยิงภาพหรือวิดีโอที่ Higgsfield |
| **ติดปัญหาที่แก้เองไม่ได้** | Chrome ไม่เชื่อมต่อ · ไม่มีไฟล์ที่ต้องใช้ · คำสั่งที่ต้องใช้ไม่มีในเครื่อง |

นอกจากสามข้อนี้ **ห้ามถามว่า "จะให้ทำต่อไหม"** — ทำต่อได้เลย
ขั้นที่พังไม่ได้แปลว่าต้องหยุดทั้งงาน **ทำขั้นที่เหลือให้จบแล้วค่อยบอกว่าขั้นไหนไม่สำเร็จเพราะอะไร**

## ทำไมต้องมีเฟสนี้

**วัดมาแล้วจากงานจริง** ตอนที่ยังมี 3 เฟส คลิปสุดท้ายต้องทำสองงานพร้อมกันใน 10 วินาที —
ติดตั้งสินค้าให้เสร็จ **และ** จัดเฟอร์นิเจอร์ ผลคือ **เฟอร์นิเจอร์ "โผล่มา" แทนที่จะถูกยกเข้ามาวาง**
เพราะโมเดลมีเวลาไม่พอกับสองงาน

พอแยกเฟสนี้ออกมา แต่ละคลิปทำหน้าที่เดียว และได้ของแถมสองอย่าง:

1. **คลิป P3→P4 กลายเป็นคลิปที่ payoff ลง** — คนยกเก้าอี้ ยกต้นไม้เข้ามาวาง ดูน่าพอใจที่สุดในคลิป
2. **รอยต่อ P2→P3 เนียนที่สุดในทั้งคลิป** เพราะทั้งสองฝั่งเป็นสภาพนิ่ง ไม่มีคนขวาง ไม่มีของกอง

## ขั้นที่ 1 — เฟสนี้ต่างจาก Phase 4 แค่เรื่องเดียว

**เอาของที่ขนเข้ามาทีหลังออกให้หมด แล้วไม่แตะอย่างอื่นเลย**

| เอาออก | คงไว้เป๊ะ |
|---|---|
| เฟอร์นิเจอร์ทุกชิ้น | **สินค้าที่ติดตั้งแล้ว — ต้องเหมือน Phase 4 ทุกจุด** |
| ต้นไม้ ของตกแต่ง ถ้วย จาน | ผนัง พื้น ฝ้า วิว แสง เงา |
| เครื่องมือ วัสดุเหลือ ผ้ากันเปื้อน | หมุดอ้างอิงทุกเส้น |
| **โคมไฟตั้งพื้น/ปักดิน** ที่ยกเข้ามาวางได้ | ⭐ **โคมไฟที่ยึดติดอาคาร — ต้องติดสว่างอยู่แล้ว** |

**พื้นต้องดูสะอาดเพิ่งกวาด** ไม่ใช่แค่ว่างเปล่า — มันคือสภาพ "ช่างเก็บงานเสร็จแล้วเพิ่งออกไป"
ต่างจาก Phase 1 ที่ต้องดูทรุดโทรมไม่มีใครดูแล

### ⭐ ไฟที่ยึดติดอาคารต้องติดอยู่แล้วใน P3 ไม่ใช่มาโผล่ใน P4

ถอดจากรีลจริง — **ไฟผนังสว่างขึ้นตั้งแต่กลางคลิป** (คลิป 25 ล้าน ติดที่ 10.0 วิ จาก 29 วิ ·
คลิป 9 ล้าน ติดที่ 8.5 วิ) แล้วค้างยาวจนจบ **ของที่จัดทีหลังจึงถูกส่องด้วยแสงอุ่นนั้นทั้งหมด**

| | อยู่เฟสไหน | กลุ่มใน `phase4.json` |
|---|---|---|
| **ไฟที่ยึดติดอาคาร** โคมผนัง โคมเพดาน ไฟใต้ชั้น | **ติดสว่างแล้วตั้งแต่ P3** | `fixed` |
| **โคมไฟตั้งพื้น/ปักดิน** ยกเข้ามาวางได้ | เข้ามาใน seg3 (P3→P4) | `styling` |

**เหตุผลเชิงโครงสร้าง:** ถ้าไฟไปโผล่ใน P4 อย่างเดียว `seg3` ต้องเสียหนึ่งเหตุการณ์ไปกับ
"เดินไปเปิดไฟ" ทั้งที่มีเวลาแค่ 8 วิสำหรับ 6–8 เหตุการณ์ และของที่จัดใน seg3 จะไม่ได้แสงนั้น

→ คีย์ `lighting` ของใบนี้ต้องเขียนว่าโคมติดอยู่ เช่น
`the wall sconces are already switched on, casting warm pools of light on the floor`

> ⚠️ **จุดที่พลาดง่ายที่สุด: สินค้าเปลี่ยนหน้าตาระหว่างเอาเฟอร์นิเจอร์ออก**
> ต้องเขียนย้ำว่า `exactly as in Image 1` กำกับตัวสินค้าเสมอ ไม่งั้นโมเดลถือโอกาสวาดใหม่

## ขั้นที่ 2 — เขียนไฟล์ (โครง JSON เดียวกับ phase1/phase2)

> ⛔ ไม่เกิน ~1,200 ตัวอักษร · ประโยคบอกเล่าล้วน · ห้ามใส่พิกัด % · ห้ามมีบล็อกคำสั่งห้ามยาวๆ
> (พรอมต์แก้ภาพที่ยาวเกินจะ **Generation failed ไปเลย** ไม่ใช่แค่ผลไม่ดี)
> JSON กินเพิ่มราว 70-100 ตัวอักษร เผื่อไว้ตอนนับ

**ค่าในทุกคีย์เป็นภาษาอังกฤษ** หัวข้อกับคำอธิบายรอบๆ เป็นไทย

````markdown
# Phase 3 — งานเสร็จ แต่ยังไม่ได้จัดของ

ยิงที่ Higgsfield · **โหมดแก้ภาพ ใส่ `frames/phase4.png` เป็นภาพตั้งต้น** · 9:16

```json
{
  "reference": "Image 1. Same <ชนิดพื้นที่>, same camera angle and position.",
  "camera": "Exact same static wide-angle position as Image 1, same <ชนิดเพอร์สเปกทีฟ>, same framing, 9:16 vertical composition. <หมุดอ้างอิง 3-4 อย่างเป็นประโยคเดียว> all stay in exactly the same place.",
  "scene": "The <ชื่องาน> work is finished but the <พื้นที่> has not been furnished yet. The floor is completely clear and freshly swept, with no furniture, no tools and no leftover material anywhere. <สิ่งที่ไม่เปลี่ยน> are unchanged.",
  "subject": "A finished but completely empty <พื้นที่>, ready to be furnished. No people, no furniture, no <ไล่ชื่อของที่ต้องหาย>.",
  "product": "<สินค้าที่ติดตั้งแล้ว> exactly as in Image 1, complete and unchanged.",
  "palette": "<โทนสีของงานที่เพิ่งเสร็จ>",
  "lighting": "Same <ทิศและช่วงเวลาแสง>, same <เงาเด่นๆ>. <โคมที่ยึดติดอาคาร> are already switched on, casting warm pools of light on <พื้นผิวที่แสงตกลง>.",
  "style": "Photorealistic, architectural documentation photography, freshly completed installation."

```
````

**บล็อกต้องเปิดด้วย ` ```json ` เป๊ะๆ** ไม่งั้น `check-phase-prompt.mjs` หาไม่เจอ

**คีย์ `product` ของใบนี้ต้องครบชุด** — P3 คือเฟรมที่โชว์สินค้าเต็มชุดครั้งแรก
ถ้าเขียนคลุมเครือ ตัวตรวจจะขึ้น ERROR และคลิป seg3 จะไม่มีอะไรให้ยกเข้ามาจัด

## ขั้นสุดท้าย

1. **วางพรอมต์เต็มใบในกล่องโค้ดให้ก๊อปได้ทันที** พร้อมบอกผลตรวจ (ERROR 0 · leak 0)
2. ย้ำว่าภาพตั้งต้นคือ `frames/phase4.png`
3. ยิงเสร็จบอกได้เลย ไม่ต้องเซฟเอง — ดึงผ่าน MCP ลง `frames/phase3.png`
4. **เปิดดูแล้ววัดหมุดเทียบทั้ง 4 เฟส เขียนตารางลง `prompts/phase3.md`**
5. คำสั่งถัดไป: `/aff-timelapse:storyboard <scene-slug>`

> 💡 **สังเกตที่เป็นประโยชน์** — การแก้ภาพมักเปิดขอบฝ้าหรือขอบบนของเฟรมขึ้นเล็กน้อยทุกครั้ง
> ผลคือ **ภาพที่ถูกแก้ (P1/P2/P3) จะตรงกันเอง และภาพหมุด (P4) จะเป็นตัวนอกกลุ่ม**
> ความเพี้ยนจึงถูกบีบไปอยู่ที่คลิปสุดท้ายคลิปเดียว ซึ่งเป็นคลิปที่มีของเข้ามาเยอะที่สุด บังได้พอดี
> **นี่เป็นข้อดี ไม่ใช่ข้อเสีย** อย่าเสียเวลาไล่แก้

## กฎเหล็ก

| เจออะไร | แปลว่า | ทำยังไงต่อ |
|---|---|---|
| ไม่มี `frames/phase4.png` | ยังไม่มีภาพหมุด | ชี้ไปที่ `/aff-timelapse:idea` แล้วหยุด |
| สินค้าเปลี่ยนหน้าตาจาก Phase 4 | ลืมย้ำ `exactly as in Image 1` | เติมแล้วยิงใหม่ **ข้อนี้ยอมไม่ได้** เพราะรอยต่อ P3→P4 จะสะดุด |
| พื้นดูรกหรือทรุดโทรม | ไปเหมือน Phase 1 | ย้ำ `completely clear and freshly swept` |
| เหลือเฟอร์นิเจอร์ติดมา | ไล่ชื่อไม่ครบ | เติมชื่อของที่เหลือลงท่อน `Subject:` แล้วยิงใหม่ |

**ห้ามเขียนพรอมต์ที่เป็น text-to-image ในสกิลนี้** ทั้งหมดต้องเป็นพรอมต์แก้ภาพเท่านั้น
