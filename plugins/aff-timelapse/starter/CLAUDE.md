# Homey Vibes — Timelapse Reels

โปรเจคทำ Reels แนว **timelapse การตกแต่ง** ของเพจ Homey Vibes
ในบ้าน · ระเบียงบ้าน/คอนโด · สวนหน้าบ้าน/หลังบ้าน โดยมีสินค้าแอฟฟิลิเอตอยู่ในคลิป

คลิปเดินเรื่อง **4 เฟส 3 คลิป** — ว่างเปล่า → ระหว่างทำ (มีคนเข้าๆ ออกๆ) → **งานเสร็จแต่ยังไม่จัดของ**
→ จัดของเสร็จ โดยกล้องนิ่งอยู่มุมเดิมเป๊ะทั้งสี่เฟส

**เอกสารหลัก:** `Timelapse_Blueprint_V1.md` — อ่านก่อนทำงานในโปรเจคนี้ทุกครั้ง
มันอธิบายเหตุผลเบื้องหลังทุกขั้นและมีเทมเพลตพรอมต์ครบ

## เครื่องมือ

## ข้อจำกัดสำคัญ (ต้องรู้)

- **วิดีโอต้องยิงบนหน้าเว็บ Higgsfield** โปรโมชั่น unlimited อยู่ที่นั่น ยิงผ่าน MCP คิดเครดิตเต็ม
  **แต่ภาพยิงผ่าน MCP ได้** ~2 เครดิต/ใบ · และ**การอ่าน/ดึงผลผ่าน MCP ฟรีเสมอ** ไม่ต้องเซฟไฟล์เอง
- **Phase 4 ต้องทำก่อนเสมอ** อีกสามเฟสเกิดจากการ **แก้ภาพ** ถอยหลังตามโซ่ **`P4 → P3 → P1 → P2`**
  ไม่ใช่ chain 1→2→3→4 ซึ่งสะสมความเพี้ยนสามทอด · **ทุกใบแก้จากภาพเดียว ห้ามใส่สองอ้างอิง**
  (สองอ้างอิง = โมเดลสังเคราะห์ฉากใหม่ ไม่ใช่แก้ภาพ · วัดได้ SSIM 0.312 แย่สุดทั้งที่ผ่านหมุดครบ)
  ⛔ **ห้ามแก้ P2 จาก P1** เพราะ P1 ไม่มีสินค้าให้ก๊อป โมเดลจะคิดพื้นขึ้นใหม่เอง
- **พอได้ `phase4.png` ให้ทำ `frames/phase4.json`** = บัญชีของทุกอย่างในภาพ (fixed · product · styling
  · lighting · **uncertain**) แล้วตรวจพรอมต์ทุกใบก่อนยิงด้วย
  `node tools/check-phase-prompt.mjs <scene-dir> prompts/phaseN.md`
  **ของในกลุ่ม `product` ที่พรอมต์ไม่เอ่ยถึงเลย = ERROR** เพราะโมเดลถือว่าเอาออกได้
- **พรอมต์ภาพทุกใบเขียนเป็น JSON** (คีย์ `reference` `camera` `scene` `subject` `product` `palette`
  `lighting` `style` · ใบ P4 เพิ่ม `critical` กับ `negative`)
  เนื้อในแต่ละคีย์ยังต้องเป็นประโยคบอกเล่า ไม่ใช่คำสั่งห้ามเรียงกัน
- ⛔ **พรอมต์วิดีโอห้ามแปลงเป็น JSON** ใช้โครง 8 บล็อก `Overall:` `Camera:` `Subject:` `Action:`
  `Lighting:` `Sound Effects:` `Dialogue: No` `Subtitles: No` เหมือนเดิม
  **เหตุผล:** โครงนั้นเป็น named fields อยู่แล้ว (แค่ใช้ `:` แทนปีกกา) ได้ประโยชน์เท่ากัน
  และวิดีโอเป็นด้านที่แพงที่สุด — ยิงบนเว็บเท่านั้น ทดสอบซ้ำไม่ได้ถูกๆ
  สถิติที่มี: JSON กับ `nano_banana_2` ผ่าน 8/8 ใบ · 8 บล็อกกับ `seedance_2_5` ผ่าน 5/5 คลิป
  **ยังไม่เคยทดสอบ JSON กับโมเดลวิดีโอเลย อย่าเดาว่าได้หรือไม่ได้**
- **พรอมต์แก้ภาพต้องไม่เกิน ~1,200 ตัวอักษร** ยาวเกิน = **Generation failed ไปเลย** ไม่ใช่แค่ผลไม่ดี
  **JSON กินเพิ่มราว 70-100 ตัวอักษร** ต้องเผื่อไว้ตอนนับ
- **`Action:` ในพรอมต์วิดีโอต้องเป็น active voice ขึ้นต้นทุกวรรคด้วย `a worker`**
  passive voice ได้ท่อนแขนลอยไม่มีคนเดินเข้ามา
  **แต่เดินออก (`and walks out`) เฉพาะวรรคสุดท้าย** วรรคอื่นตัดจบตอนทำเสร็จ · **3–4 วรรค ไม่ใช่ 7–8**
  (การตัด `walks in` ออกไม่ได้ทำให้กลับเป็น passive — บั๊กแขนลอยมาจากการเอา*สิ่งของ*ขึ้นเป็นประธาน)
- **งานในคลิปเรียงตามลำดับ A/B/C** `seg1` เตรียมพื้นที่+ลงพื้น(เริ่ม) · `seg2` ลงพื้น(จบ)+งานยึดติด+ไฟผนังติด
  · `seg3` ของหนัก→ของเล็ก→ชิ้นเอกที่กางออก+โคมไฟตั้งพื้น **ขั้นข้ามช่วงไม่ได้**
- **`phase2.png` ต้องคืบแค่ราวหนึ่งในสามถึงครึ่ง ไม่ใช่เกือบครบ** เพราะงานทั้ง `seg2` คือส่วนต่าง P2→P3
  ถ้า P2 คืบไปเกือบหมด **seg2 ไม่มีงานเหลือ แล้วโมเดลจะถมเวลาด้วยการทำงานซ้ำที่เดิมกับ seg1**
  (เกิดแล้วจริง: P2 ติดตั้งไป 8 จาก 11 ส่วน · **ตัวตรวจให้ผ่านหมด ✅ 22 · ❌ 0** เพราะมองไม่เห็นข้อนี้)
  **ตั้งตัวเลขคืบหน้าโดยถามว่า "เหลืออะไรให้ seg2 ทำ 8 วินาที"**
- **กริยาต้องตรงกับน้ำหนักของ** หนักใหญ่ = `drags`/`slides` ไม่ใช่ `carries` · ยาวเป็นมัด = หอบมัดเดียว
  · เล็ก = ทีละ 1–2 ชิ้น **ใช้ `a worker` คนเดียวเป็นค่าเริ่มต้น** สองคนยกอะไรก็ได้ ของหนักเลยไม่เคยถูกลาก
- **ของที่กินเวลา ≥ 2 วิ ใส่ได้ไม่เกิน 2 ชิ้นต่อคลิป** เกินกว่านี้ภาพค้างกับของชิ้นเดิมนานเกินไป คลิปน่าเบื่อ
- **โคลสอัพต้องกำกับเวลาใน `Camera:`** ระบุเป็นวินาที + บอกว่ามือทำอะไร · 2–3 ครั้ง/คลิป
  **ห้ามมีคัตใน 1 วินาทีสุดท้าย** เฟรมจบต้องตรงกับภาพนิ่งเฟสถัดไป ไม่งั้นรอยต่อ F2F ขาด
- **แขนถูกขอบเฟรมตัด ≠ แขนตัดขาดกลางเฟรม** อย่างแรกคือโคลสอัพที่ตั้งใจ **ทำได้**
  อย่างหลังคือบั๊กแขนลอย **ห้าม** — `Subject:` ต้องเขียนว่าแขนทุกเส้นวิ่งออกนอกขอบเฟรมและต่อกับตัวคน
- **ไฟที่ยึดติดอาคารต้องติดสว่างตั้งแต่ `phase3.png`** เป็นกลุ่ม `fixed` ไม่ใช่ `styling`
  (โคมไฟตั้งพื้นที่ยกเข้ามาวางได้ ถึงจะเป็น `styling` ของ seg3)
- **`phase4.png` ต้องไม่ซีด** — ไฟดวงจริงติดในเฟรม ≥2 ดวง · ของแต่ง ~10–12 ชิ้นเป็นชั้น
  · ผ้ามีลายมีสี ≥1 ชิ้น · ของบังหน้าเฟรมสร้างระยะ **เกณฑ์ `SATAVG ≥ 18`**
- **วัสดุของงาน seg3 ห้ามอยู่ในเฟรมก่อน seg3** `วัสดุกองรอ` ใน P2 ต้องเป็นวัสดุของงาน P2→P3 เท่านั้น
  ไม่งั้นได้ลำดับ **เข้า → ออก → เข้า** ซึ่งขัดสามัญสำนึกคนดู (เกิดมาแล้วทั้งสองฉากของสินค้าศาลา)
  **ห้ามแก้ด้วยการยัดวัสดุเข้า P3** เพราะ P3 คือเฟรมโชว์สินค้าครบชุด ต้องสะอาด
- **`phase2.png` กับ `phase3.png` ห้าม regen หลังจากพอใจแล้ว** ทั้งสองใบถูกใช้ใบละสองครั้ง
  เป็นเฟรมจบของคลิปหนึ่งและเฟรมเริ่มของคลิปถัดไป ยิงใหม่ = รอยต่อกระตุก
- **ตรวจด้วยคำสั่ง ไม่ใช่ด้วยตา** → `node tools/check-scene.mjs scenes/<slug>` (ดูหัวข้อจุดตรวจข้างล่าง)
  เคยปล่อยคลิปแขนลอยผ่านมาแล้วเพราะดูผ่านๆ
- **เสียงมาจากโมเดลวิดีโอ (ASMR)** ไม่มีเสียงพากย์ ไม่มี BGM — **ต้องเปิดสวิตช์ Sound ตอนยิง**
  ลืมแล้วต้องยิงใหม่ทั้งคลิป แก้ทีหลังไม่ได้
- **`final/reel.mp4` ต้องไม่มีตัวหนังสือบนจอ** ส่งไฟล์ภาพกับเสียงล้วน ผู้ใช้จัดการชั้นตัวหนังสือเอง
  (และห้าม bake ตัวหนังสือลงในพรอมต์ภาพด้วย AI วาดเพี้ยนทุกครั้ง)
- **ห้ามใส่ราคาในคลิป** ราคาบน Shopee เปลี่ยนตลอด คลิปอยู่ยาวกว่าราคา
- **ห้ามใส่ลิงก์ในตัวแคปชัน** เอาไปวางคอมเมนต์แรก
- **ห้ามแต่งข้อมูลสินค้า** อ่านหน้า Shopee ไม่ได้ให้บอกว่าอ่านไม่ได้

## จุดตรวจที่วัดได้ — จบทีละงาน ห้ามข้ามไปงานถัดไปทั้งที่ยังแดง

```bash
node tools/check-scene.mjs scenes/<slug>                    # ตรวจทุกด่าน
node tools/check-scene.mjs scenes/<slug> --stage frames     # ตรวจเฉพาะด่านที่กำลังทำ
node tools/check-scene.mjs scenes/<slug> --probe            # กวาดหาหมุดให้เอง แล้วก๊อปไปใส่ phase4.json
node tools/contact-sheet.mjs scenes/<slug>                  # แผ่นเทียบ 4 เฟส + กรอบโซนที่ SSIM วัด
node tools/probe-band.mjs scenes/<slug> --heatmap           # กวาดหา static_band ให้เอง (ต้องมีครบ 4 ใบ)
```

**พอได้ภาพครบสี่ใบของฉากใหม่ ต้อง `ปรับ static_band ใหม่ทั้งหมด` ด้วย `probe-band` เสมอ**
ร่างที่ตั้งไว้ตอนมี P4 ใบเดียวยังไม่เคยถูกวัด · เครื่องจะบอกเองถ้าของเดิมดีกว่า
**แล้วต้องเปิด `_band-probe.png` กับ `_contact-sheet.png` ยืนยันด้วยตาก่อนรับทุกครั้ง**

| ด่าน | รันเมื่อ | วัดอะไร |
|---|---|---|
| `frames` | ได้ภาพครบ 4 เฟส | ขนาดเท่ากัน · หมุดล็อกไม่เกิน 2% · ความสว่างไม่กระโดด · มี `phase4.json` · **ภาพจบไม่ซีด SATAVG ≥ 18** · **องค์ประกอบโซนที่ห้ามเปลี่ยน (SSIM)** |
| `prompts` | ก่อนยิง P1-P3 | ERROR 0 · styling-leak 0 (เรียก `check-phase-prompt.mjs` ให้เอง) |
| `clips` | โหลดคลิปมาแล้ว | ยาว 8 วิ · มีเสียงจริง · **จบตรงเฟสที่ควรจบ** · กล้องไม่เลื่อนในคลิป · เฟรมจบตรงกับภาพนิ่ง · **จำนวนคัต + ห้ามมีคัตใน 1 วิสุดท้าย** |
| `reel` | ต่อเสร็จ | ยาว = ผลรวมคลิป + 2 · มีเสียง · **ไม่มีสตรีมซับ** · ขนาดตรงคลิป |
| `caption` | เขียนแคปชันแล้ว | ครบ 3 แบบ · ไม่มีลิงก์ในบอดี้ · ไม่มีราคา |

**ทุกข้อที่แดงต้องจบด้วยอย่างใดอย่างหนึ่ง — แก้ให้เขียว หรือเขียนเหตุผลลง `scenes/<slug>/qa-accepted.json`**
เหตุผลต้องยาวอย่างน้อย 30 ตัวอักษร ไม่งั้นยังนับเป็น FAIL อยู่ · แก้แล้วให้ลบคีย์ทิ้ง เครื่องตรวจเตือนเองว่ามีคีย์ค้าง
**ห้ามปล่อยให้มีข้อแดงค้างเงียบๆ** เพราะข้อแดงที่ข้ามไปจะกลับมาเป็นงานยิงใหม่ที่แพงกว่าเสมอ

**บทเรียนจากตัวเครื่องตรวจเอง — วิธีวัดที่ดูสมเหตุสมผลแต่ตัดสินผิด:**

| วัดด้วย | พังตรงไหน |
|---|---|
| หมุดเดี่ยว (ขอบแรงที่สุดในช่วง) กับ**เฟรมวิดีโอ** | ของที่เดินผ่านหน้าเลนส์ทำให้ขอบสลับตัว อ่านได้ว่าเลื่อน 11.6% ทั้งที่จริง 0.5% |
| หมุดเดี่ยวกับ**ภาพนิ่ง ในคอลัมน์ที่สินค้าไปตั้งอยู่** | ของในคอลัมน์เปลี่ยนไปตามเฟส ขอบที่แรงที่สุดจึงสลับเส้น อ่านได้ว่าเลื่อน 5.6% ทั้งที่ correlation ให้ r=0.99 เลื่อน 0.00% |
| PSNR ทั้งเฟรม | คน 1 คนที่กินพื้นที่ 20% ของภาพนิ่งดันคะแนนลงจนเฟสผิดใบชนะ |
| ค่ากลางผลต่างรายพิกเซล | พื้น/ฝ้า/ผนังเรียบที่เหมือนกันทุกเฟสกลบจนแยกเฟสไม่ออก |
| ✅ **correlation ของลายเส้น** | ใช้ได้ — พื้นที่เรียบให้ค่าศูนย์ ส่วนที่ต่างจริงระหว่างเฟสล้วนเป็นลายเส้น |
| ✅ **cross-correlation หาค่าเลื่อน + เอาค่ากลางหลายคอลัมน์** | ใช้ได้ — ของบังได้ทีละคอลัมน์ แต่ขยับค่ากลางไม่ได้ |

**หมุดเดี่ยวเชื่อได้เฉพาะคอลัมน์ที่ของไม่เปลี่ยนตามเฟส** ตัวเลข % ในการ์ด CAMERA LOCK อ่านง่ายสำหรับคน
แต่พอหมุดเกินเกณฑ์ **ห้ามสรุปว่ากล้องเลื่อนทันที** — `check-scene.mjs` จะถาม correlation ของคอลัมน์เดิมให้เอง
แล้วลดเป็น WARN ถ้า correlation (r ≥ 0.5) บอกว่าเลื่อน 0% · จะ FAIL ก็ต่อเมื่อ correlation ยืนยันด้วย

**⛔ หมุดตรงยังไม่ใช่คำว่า "ผ่าน" — ผ่าน = องค์ประกอบเหมือน P4 ที่ถอยเวลากลับมา**
หมุด 3-4 คอลัมน์เป็นสายสะดุดราคาถูก มันมองไม่เห็นว่าที่เหลือของเฟรมถูกวาดใหม่หรือเปล่า
เคสจริง: ใบ P2 ที่ยิงด้วย**สองอ้างอิง**ได้ SSIM โซนนิ่งแค่ 0.312 แย่สุดในสี่ใบที่เทียบ **แต่ผ่านหมุดทั้งสามเส้น**
เพราะคอลัมน์ที่เลือกบังเอิญตกบนขอบที่ตรงกัน → ด่าน `องค์ประกอบโซนที่ห้ามเปลี่ยน` จึงมีไว้จับข้อนี้

| ประเด็น | กติกา |
|---|---|
| เทียบกับใบไหน | **ใบต้นทางในโซ่** ไม่ใช่ P4 ทุกใบ — โซ่ปกติ `P4 → P3 → P1 → P2` ทับได้ที่ `"chain": {"1":3,"2":3,"3":4}` |
| ทำไมไม่เทียบ P4 หมด | ทุกการยิงกินคุณภาพหนึ่งทอด P1 ที่ห่าง P4 สองทอดจะแพ้ P3 ตลอดทั้งที่ไม่ผิดอะไร |
| โซนที่วัด | ปริยาย **บน 40%** · ทับได้ที่ `"static_band": {"x":0,"y":0,"w":1,"h":0.4}` ใน `phase4.json` · **ใส่เป็น array หลายกล่องได้** เครื่องเฉลี่ยถ่วงน้ำหนักด้วยพื้นที่ให้ |
| ของที่ไม่ใช่ `fixed` โผล่เข้าโซน | **นับเป็นของฝั่งเปลี่ยนได้ แล้วเว้นตัวมันออกจากโซน** ด้วย `static_band` หลายกล่อง · ดูที่ `from_phase` เป็นตัวชี้ ถึงของชิ้นนั้นจะอยู่ในลิสต์ `fixed` ก็ตาม · ⛔ ห้ามแก้ด้วยการระบายทับ เพราะพิกเซลเหมือนกันเป๊ะได้ SSIM 1.0 แล้วเจือค่าจริงให้สูงเกินจริง |
| เลือกโซนยังไง | **ให้ `probe-band` วัดแล้วเลือก อย่าเลือกด้วยตา** — เอามาใช้กับสามฉากที่ทำเสร็จแล้ว ชนะที่เลือกด้วยมือทั้งสามฉาก (0.080→0.072 · 0.038→0.019 · 0.058→0.017) |
| พื้นผิวไหนน่าเริ่มมอง | **ผนัง/ฝ้า/รั้วทึบ/พื้นเรียบ** (0.099) → ฉากหลังไกล (0.082) → เลี่ยง**ใบไม้ใกล้** (0.148) → ⛔ **ผนังที่มีเงาใบไม้ทาบ** (0.253) · **แต่เป็นแค่จุดตั้งต้น ไม่ใช่คำตัดสิน** — กล่องที่ชนะของฉากหนึ่งคาบเถาวัลย์อยู่บ้างแต่ยังชนะทุกกล่องที่เลือกด้วยมือ |
| หลายกล่องดีกว่าเสมอไหม | **ไม่** — เป็นเครื่องมือ**เว้นของ** ไม่ใช่เครื่องมือ**ขยายโซน** · สามฉากที่ทำมาได้ 1, 2 และ 3 กล่องต่างกัน **ให้เครื่องเป็นคนบอก** |
| โซนต้องเป็นอะไร | **ผนัง รั้ว ฝ้า ต้นไม้ใหญ่ ที่ไม่มีงานเกิดขึ้นเลยทั้งสี่เฟส** — ถ้ามี styling/product/คนงานโผล่เข้ามา ค่าจะตกเพราะของที่*ควร*เปลี่ยน ไม่ใช่เพราะฉากเพี้ยน |
| สะอาดแค่ไหนถึงพอ | **ดูขนาด ไม่ใช่ดูว่ามีหรือไม่มี** — ของชิ้นเดียวเล็กๆ ในแถบแทบไม่ขยับค่า (วัดแล้วต่าง 0.005-0.008 = noise) · ที่ทำให้พังคือของที่**กระจายทั่วแถบ** |
| อยากเห็นโซนด้วยตา | `node tools/contact-sheet.mjs scenes/<slug>` → `frames/_contact-sheet.png` สี่เฟสเรียงกันพร้อมกรอบแดงทับโซนที่วัด |
| ตัดสินยังไง | **เทียบอันดับในฉากเดียวกัน ไม่ใช่ค่าสัมบูรณ์** — ห่างจากใบดีสุด >0.10 = WARN · >0.15 = FAIL |
| ทำไมไม่ใกล้ 1.0 | ทุกใบเป็น generative edit ที่เรนเดอร์ใหม่ทั้งภาพ ไม่ใช่ inpaint ที่แปะเฉพาะโซน · 0.55-0.85 คือช่วงปกติ |

ตัวเลขที่วัดไว้: ฉากที่รับแล้วห่างกันเอง **0.08-0.13** · ใบที่ตาเห็นว่าวาดใหม่ห่าง **0.21** · ใบสองอ้างอิงห่าง **0.34**
