# Homey Vibes — Timelapse Reels

โปรเจคทำ Reels แนว **timelapse การตกแต่ง** ของเพจ Homey Vibes
ในบ้าน · ระเบียงบ้าน/คอนโด · สวนหน้าบ้าน/หลังบ้าน โดยมีสินค้าแอฟฟิลิเอตอยู่ในคลิป

คลิปเดินเรื่อง **4 เฟส 3 คลิป** — ว่างเปล่า → ระหว่างทำ (มีคนเข้าๆ ออกๆ) → **งานเสร็จแต่ยังไม่จัดของ**
→ จัดของเสร็จ โดยกล้องนิ่งอยู่มุมเดิมเป๊ะทั้งสี่เฟส

**เอกสารหลัก:** `Timelapse_Blueprint_V1.md` — อ่านก่อนทำงานในโปรเจคนี้ทุกครั้ง
มันอธิบายเหตุผลเบื้องหลังทุกขั้นและมีเทมเพลตพรอมต์ครบ

## เครื่องมือ

ปลั๊กอิน **`aff-timelapse`** (ติดตั้งจาก marketplace `homey-vibes` หรือวางที่ `~/.claude/skills/aff-timelapse/`)

| คำสั่ง | ทำอะไร |
|---|---|
| `/aff-timelapse:scene <ลิงก์>` | ครบทั้งเส้น (มีจุดหยุดรอ 3 จุด) |
| `/aff-timelapse:product <ลิงก์>` | เก็บสินค้าจาก Shopee |
| `/aff-timelapse:idea <slug>` | ไอเดีย 4 แบบให้กดเลือก → CAMERA LOCK + พรอมต์ **Phase 4 (ภาพหมุด)** |
| `/aff-timelapse:phase3 <scene>` | พรอมต์แก้ภาพ → งานเสร็จ แต่ยังไม่จัดของ |
| `/aff-timelapse:phase2 <scene>` | พรอมต์แก้ภาพ → ระหว่างทำ |
| `/aff-timelapse:phase1 <scene>` | พรอมต์แก้ภาพ → ว่างเปล่า |
| `/aff-timelapse:storyboard <scene>` | สตอรีบอร์ด F2F **3 ช่วง ช่วงละ 8 วิ** + ตรวจคลิป |
| `/aff-timelapse:assemble <scene>` | รวมคลิป 9:16 ด้วย ffmpeg |
| `/aff-timelapse:study <ลิงก์รีล>` | **ขาเข้า** — ถอดโครงช็อตจากรีลเพจอื่น สะสมลง `timelapse_master_prompt.md` |

## โครงสร้างโฟลเดอร์

```
products/<slug>/          คลังสินค้า ใช้ซ้ำข้ามฉากได้
├── product.md · design.md · refsheet.md
├── images/main · images/description
└── seeds/                รูปที่ใช้เป็น reference ได้
    └── refsheet.png      ← reference หลักของทุกฉาก ไม่ใช่รูปหน้าร้าน

scenes/<scene-slug>/      1 โฟลเดอร์ = 1 คลิป
├── scene.md              ไอเดีย + CAMERA LOCK CARD (วัดจากภาพหมุดจริง)
├── prompts/              phase4.md ← หมุด · phase3.md · phase2.md · phase1.md
├── frames/               phase1-4.png · _rejected/ ภาพที่ไม่ผ่าน พร้อมชื่อบอกอาการ
├── storyboard.md         3 ช่วง + กฎ active voice + ขั้นตรวจคลิป
├── clips/                seg1.mp4 · seg2.mp4 · seg3.mp4 · _rejected/
└── final/                reel.mp4 + caption.md
```

## ข้อจำกัดสำคัญ (ต้องรู้)

- **วิดีโอต้องยิงบนหน้าเว็บ Higgsfield** โปรโมชั่น unlimited อยู่ที่นั่น ยิงผ่าน MCP คิดเครดิตเต็ม
  **แต่ภาพยิงผ่าน MCP ได้** ~2 เครดิต/ใบ · และ**การอ่าน/ดึงผลผ่าน MCP ฟรีเสมอ** ไม่ต้องเซฟไฟล์เอง
- **Phase 4 ต้องทำก่อนเสมอ** อีกสามเฟสเกิดจากการ **แก้ภาพ** Phase 4 **แก้จากหมุดโดยตรงทุกใบ**
  ไม่ใช่ chain 1→2→3→4 ซึ่งสะสมความเพี้ยนสามทอด
- **พอได้ `phase4.png` ให้ทำ `frames/phase4.json`** = บัญชีของทุกอย่างในภาพ (fixed · product · styling
  · lighting · **uncertain**) แล้วตรวจพรอมต์ทุกใบก่อนยิงด้วย
  `node tools/check-phase-prompt.mjs <scene-dir> prompts/phaseN.md`
  **ของในกลุ่ม `product` ที่พรอมต์ไม่เอ่ยถึงเลย = ERROR** เพราะโมเดลถือว่าเอาออกได้
- **พรอมต์ภาพทุกใบเขียนเป็น JSON** (คีย์ `reference` `camera` `scene` `subject` `product` `palette`
  `lighting` `style` · ใบ P4 เพิ่ม `critical` กับ `negative`)
  เนื้อในแต่ละคีย์ยังต้องเป็นประโยคบอกเล่า ไม่ใช่คำสั่งห้ามเรียงกัน
- ⛔ **พรอมต์วิดีโอห้ามแปลงเป็น JSON** ใช้โครง 8 บล็อก `Overall:` `Camera:` `Subject:` `Action:`
  `Lighting:` `Sound Effects:` `Dialogue: No` `Subtitles: No` เหมือนเดิม
  **เหตุผล:** โครงนั้นเป็น named fields อยู่แล้ว (แค่ใช้ `:` แทนปีกกา) ได้ประโยชน์เท่ากัน
  และวิดีโอเป็นด้านที่แพงที่สุด — ยิงบนเว็บเท่านั้น ทดสอบซ้ำไม่ได้ถูกๆ
  สถิติที่มี: JSON กับ `nano_banana_2` ผ่าน 8/8 ใบ · 8 บล็อกกับ `seedance_2_5` ผ่าน 5/5 คลิป
  **ยังไม่เคยทดสอบ JSON กับโมเดลวิดีโอเลย อย่าเดาว่าได้หรือไม่ได้**
- **พรอมต์แก้ภาพต้องไม่เกิน ~1,200 ตัวอักษร** ยาวเกิน = **Generation failed ไปเลย** ไม่ใช่แค่ผลไม่ดี
  **JSON กินเพิ่มราว 70-100 ตัวอักษร** ต้องเผื่อไว้ตอนนับ
- **`Action:` ในพรอมต์วิดีโอต้องเป็น active voice ขึ้นต้นทุกวรรคด้วย `a worker`**
  passive voice ได้ท่อนแขนลอยไม่มีคนเดินเข้ามา
- **วัสดุของงาน seg3 ห้ามอยู่ในเฟรมก่อน seg3** `วัสดุกองรอ` ใน P2 ต้องเป็นวัสดุของงาน P2→P3 เท่านั้น
  ไม่งั้นได้ลำดับ **เข้า → ออก → เข้า** ซึ่งขัดสามัญสำนึกคนดู (เกิดมาแล้วทั้งสองฉากของสินค้าศาลา)
  **ห้ามแก้ด้วยการยัดวัสดุเข้า P3** เพราะ P3 คือเฟรมโชว์สินค้าครบชุด ต้องสะอาด
- **`phase2.png` กับ `phase3.png` ห้าม regen หลังจากพอใจแล้ว** ทั้งสองใบถูกใช้ใบละสองครั้ง
  เป็นเฟรมจบของคลิปหนึ่งและเฟรมเริ่มของคลิปถัดไป ยิงใหม่ = รอยต่อกระตุก
- **ตรวจด้วยคำสั่ง ไม่ใช่ด้วยตา** → `node tools/check-scene.mjs scenes/<slug>` (ดูหัวข้อจุดตรวจข้างล่าง)
  เคยปล่อยคลิปแขนลอยผ่านมาแล้วเพราะดูผ่านๆ
- **เสียงมาจากโมเดลวิดีโอ (ASMR)** ไม่มีเสียงพากย์ ไม่มี BGM — **ต้องเปิดสวิตช์ Sound ตอนยิง**
  ลืมแล้วต้องยิงใหม่ทั้งคลิป แก้ทีหลังไม่ได้
- **`final/reel.mp4` ต้องไม่มีตัวหนังสือบนจอ** ส่งไฟล์ภาพกับเสียงล้วน ผู้ใช้จัดการชั้นตัวหนังสือเอง
  (และห้าม bake ตัวหนังสือลงในพรอมต์ภาพด้วย AI วาดเพี้ยนทุกครั้ง)
- **ห้ามใส่ราคาในคลิป** ราคาบน Shopee เปลี่ยนตลอด คลิปอยู่ยาวกว่าราคา
- **ห้ามใส่ลิงก์ในตัวแคปชัน** เอาไปวางคอมเมนต์แรก
- **ห้ามแต่งข้อมูลสินค้า** อ่านหน้า Shopee ไม่ได้ให้บอกว่าอ่านไม่ได้

## จุดตรวจที่วัดได้ — จบทีละงาน ห้ามข้ามไปงานถัดไปทั้งที่ยังแดง

```bash
node tools/check-scene.mjs scenes/<slug>                    # ตรวจทุกด่าน
node tools/check-scene.mjs scenes/<slug> --stage frames     # ตรวจเฉพาะด่านที่กำลังทำ
node tools/check-scene.mjs scenes/<slug> --probe            # กวาดหาหมุดให้เอง แล้วก๊อปไปใส่ phase4.json
```

| ด่าน | รันเมื่อ | วัดอะไร |
|---|---|---|
| `frames` | ได้ภาพครบ 4 เฟส | ขนาดเท่ากัน · หมุดล็อกไม่เกิน 2% · ความสว่างไม่กระโดด · มี `phase4.json` |
| `prompts` | ก่อนยิง P1-P3 | ERROR 0 · styling-leak 0 (เรียก `check-phase-prompt.mjs` ให้เอง) |
| `clips` | โหลดคลิปมาแล้ว | ยาว 8 วิ · มีเสียงจริง · **จบตรงเฟสที่ควรจบ** · กล้องไม่เลื่อนในคลิป · เฟรมจบตรงกับภาพนิ่ง |
| `reel` | ต่อเสร็จ | ยาว = ผลรวมคลิป + 2 · มีเสียง · **ไม่มีสตรีมซับ** · ขนาดตรงคลิป |
| `caption` | เขียนแคปชันแล้ว | ครบ 3 แบบ · ไม่มีลิงก์ในบอดี้ · ไม่มีราคา |

**ทุกข้อที่แดงต้องจบด้วยอย่างใดอย่างหนึ่ง — แก้ให้เขียว หรือเขียนเหตุผลลง `scenes/<slug>/qa-accepted.json`**
เหตุผลต้องยาวอย่างน้อย 30 ตัวอักษร ไม่งั้นยังนับเป็น FAIL อยู่ · แก้แล้วให้ลบคีย์ทิ้ง เครื่องตรวจเตือนเองว่ามีคีย์ค้าง
**ห้ามปล่อยให้มีข้อแดงค้างเงียบๆ** เพราะข้อแดงที่ข้ามไปจะกลับมาเป็นงานยิงใหม่ที่แพงกว่าเสมอ

**บทเรียนจากตัวเครื่องตรวจเอง — วิธีวัดที่ดูสมเหตุสมผลแต่ตัดสินผิด:**

| วัดด้วย | พังตรงไหน |
|---|---|
| หมุดเดี่ยว (ขอบแรงที่สุดในช่วง) กับ**เฟรมวิดีโอ** | ของที่เดินผ่านหน้าเลนส์ทำให้ขอบสลับตัว อ่านได้ว่าเลื่อน 11.6% ทั้งที่จริง 0.5% |
| หมุดเดี่ยวกับ**ภาพนิ่ง ในคอลัมน์ที่สินค้าไปตั้งอยู่** | ของในคอลัมน์เปลี่ยนไปตามเฟส ขอบที่แรงที่สุดจึงสลับเส้น อ่านได้ว่าเลื่อน 5.6% ทั้งที่ correlation ให้ r=0.99 เลื่อน 0.00% |
| PSNR ทั้งเฟรม | คน 1 คนที่กินพื้นที่ 20% ของภาพนิ่งดันคะแนนลงจนเฟสผิดใบชนะ |
| ค่ากลางผลต่างรายพิกเซล | พื้น/ฝ้า/ผนังเรียบที่เหมือนกันทุกเฟสกลบจนแยกเฟสไม่ออก |
| ✅ **correlation ของลายเส้น** | ใช้ได้ — พื้นที่เรียบให้ค่าศูนย์ ส่วนที่ต่างจริงระหว่างเฟสล้วนเป็นลายเส้น |
| ✅ **cross-correlation หาค่าเลื่อน + เอาค่ากลางหลายคอลัมน์** | ใช้ได้ — ของบังได้ทีละคอลัมน์ แต่ขยับค่ากลางไม่ได้ |

**หมุดเดี่ยวเชื่อได้เฉพาะคอลัมน์ที่ของไม่เปลี่ยนตามเฟส** ตัวเลข % ในการ์ด CAMERA LOCK อ่านง่ายสำหรับคน
แต่พอหมุดเกินเกณฑ์ **ห้ามสรุปว่ากล้องเลื่อนทันที** — `check-scene.mjs` จะถาม correlation ของคอลัมน์เดิมให้เอง
แล้วลดเป็น WARN ถ้า correlation (r ≥ 0.5) บอกว่าเลื่อน 0% · จะ FAIL ก็ต่อเมื่อ correlation ยืนยันด้วย
